## คำถามวิจัย
จะรวม LLM กับเวกเตอร์ฝังตัวข้อความเข้ากับการจำแนก ESCO เพื่อสกัดทักษะและอาชีพจากประกาศงาน
และข้อความทั่วไปที่ไม่มีโครงสร้างได้อย่างไร พร้อมเครื่องมือโอเพนซอร์สที่นักวิจัยและผู้ปฏิบัติใช้ได้จริง

## ข้อจำกัดของวิธีเดิม
การสกัดทักษะที่อิงคำสำคัญแบบดั้งเดิมจับความหลากหลายเชิงความหมายไม่ได้ และจัดให้ตรงกับ
การจำแนกมาตรฐานอย่างน่าเชื่อถือไม่ได้ ส่วนเครื่องมือที่มีอยู่ไม่จัดให้ตรงกับ ESCO ต้องใช้ API
เชิงพาณิชย์ หรือขาดส่วนติดต่อผู้ใช้ที่คนไม่ใช่นักพัฒนาใช้ได้ ไม่มีเครื่องมือโอเพนซอร์สที่รวม
LLM + เวกเตอร์ฝังตัว + การจำแนก ESCO ไว้ในสายงานเดียว

## ผลงาน
ESCOX (ESCOSkillExtractor) — เครื่องมือ Python โอเพนซอร์สที่รวม LLM กับเวกเตอร์ฝังตัวของ ESCO
เพื่อสกัดทักษะและอาชีพจากประกาศงาน มีส่วนติดต่อผู้ใช้แบบเว็บ ติดตั้งด้วย pip และใช้งานจริง
ในโครงการ SKILLAB ของ EU Horizon จัดการทั้งทักษะและการจำแนกอาชีพ (ISCO-08) ในสายงานเดียว

## วิธีที่เสนอ
- **สายงาน:** ข้อความเข้า → การตรวจจับช่วงทักษะด้วย LLM → การจับคู่ด้วยความคล้ายของ
  เวกเตอร์ฝังตัว ESCO → การจำแนกทักษะ/อาชีพ
- **การจำแนก:** ESCO + รหัสอาชีพ ISCO-08
- **เวกเตอร์ฝังตัว:** เวกเตอร์ฝังตัวทักษะ ESCO (sentence-transformers) สำหรับการจับคู่เชิงความหมาย
- **LLM:** ใช้สกัดช่วงข้อความและสรุป
- **ส่วนติดต่อผู้ใช้:** เว็บแอป Flask + REST API และสมุด Google Colab
- **กรณีศึกษา:** ประกาศงานวิศวกรรมซอฟต์แวร์ราว 6,500 รายการจาก EURES จำแนกเป็น 4 กลุ่ม ISCO-08
- **ทักษะอันดับต้นที่สกัดได้:** Java, SQL, DevOps, "ทำงานอย่างอิสระ", Python, Agile, การสื่อสาร

## ข้อค้นพบสำคัญ
- สายงาน LLM + เวกเตอร์ฝังตัวสกัดทั้งทักษะเชิงเทคนิคและทักษะทางสังคมได้สำเร็จ และจัดแต่ละตัว
  ให้ตรงกับรายการในการจำแนก ESCO
- ทักษะงานวิศวกรรมซอฟต์แวร์ที่ครองข้อมูล EU EURES: Java, SQL, DevOps, Python, Agile
  ซึ่งสอดคล้องกับความคาดหวังของภาคอุตสาหกรรม
- การแจกแจงอาชีพ ISCO-08: นักวิเคราะห์ธุรกิจ ICT ผู้จัดการโครงการ และนักวิทยาการคอมพิวเตอร์
  ครองประกาศงานวิศวกรรมซอฟต์แวร์ที่สกัดได้
- เป็นโอเพนซอร์ส ติดตั้งด้วย pip (`pip install esco-skill-extractor`) สัญญาอนุญาต MIT
  จึงมีศักยภาพการนำไปใช้ซ้ำสูงสุด
- เครื่องมือเชื่อม "คนคนหนึ่งทำอะไรได้" (ทักษะ) กับ "คนคนหนึ่งมีคุณสมบัติสำหรับอะไร" (อาชีพ)
  การสกัดคู่ขนานนี้เป็นข้อได้เปรียบเชิงการออกแบบ

## ข้อจำกัดของบทความนี้
ESCOX พึ่งการจำแนก ESCO ทั้งหมด ทักษะที่ไม่อยู่ใน ESCO (ที่เกิดใหม่ เฉพาะสาขา เฉพาะภูมิภาค)
จะถูกพลาดหรือจำแนกผิด · ESCO ไม่ครอบคลุมทักษะภาษาไทยหรือคำศัพท์ในบริบทไทย ·
กรณีศึกษาจำกัดที่ตลาดแรงงาน EU ไม่มีการประเมินบนประกาศงานนอกยุโรปหรือที่ไม่ใช่ภาษาอังกฤษ ·
และไม่มีการประเมินความแม่นยำ/ความครบถ้วนที่ตีพิมพ์เทียบกับชุดข้อมูลทักษะที่กำกับและกันไว้

## บันทึกสำหรับ Iris
**เอกสารอ้างอิงเชิงสถาปัตยกรรมสำหรับวิศวกร AI ของเรา** สายงาน LLM + เวกเตอร์ฝังตัว +
การจำแนกใน ESCOX มีโครงสร้างคล้ายสิ่งที่ Iris ต้องการ แต่ ESCO ใช้กับบริบทไทยไม่ได้
ข้อสรุปสำคัญ: การแยก (1) การตรวจจับช่วงข้อความด้วย LLM ออกจาก (2) การจัดให้ตรงกับการจำแนก
ด้วยความคล้ายของเวกเตอร์ฝังตัว เป็นการออกแบบสองขั้นที่สะอาดซึ่งเราควรรับมาใช้ — โดยใช้
คลังทักษะไทยของเราแทน ESCO ในขั้นการจัดให้ตรง ส่วนทักษะอันดับต้นจากกรณีศึกษา ESCOX
(Java, SQL, Python, Agile) ให้การตรวจสอบไขว้: หากประกาศงาน CS ไทยของเราไม่ให้ทักษะ
คล้ายกันใน top-N แสดงว่ามีอะไรผิดกับการสกัดของเรา และสัญญาอนุญาต MIT แบบโอเพนซอร์ส
แปลว่าเราตรวจสอบและปรับโค้ดสายงานได้โดยตรง
