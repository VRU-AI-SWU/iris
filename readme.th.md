# Iris — การจับคู่หลักสูตรกับทักษะ

<!-- lang-switch -->
[English](readme.md) · **ภาษาไทย**

> **สาขา:** อุดมศึกษาไทย · การวิเคราะห์หลักสูตร
> **อ้างอิงมาตรฐาน:** [Thailand Skill Mapping](https://www.skillmapping.in.th/en) — มาตรฐานทักษะแห่งชาติ เผยแพร่โดย สป.อว. พัฒนาโดย สจล.
> **สถานะ:** ระยะที่ 4 — การพัฒนาระบบ, Sprint 4 *(ออกแบบใหม่ 2026-08-27)*

---

## ระบบนี้ทำอะไร

มาตรฐาน Thailand Skill Mapping อธิบายว่าแต่ละอาชีพต้องการทักษะใดบ้าง ด้วยคลังคำศัพท์ควบคุม
**4,376 ทักษะ** ครอบคลุม **371 อาชีพ** มาตรฐานนิยามจุดมุ่งหมายของตนเองว่าคือการเชื่อม
*ฝั่งอุปสงค์* เข้ากับ *ฝั่งอุปทาน* — สิ่งที่ตลาดแรงงานต้องการ กับสิ่งที่หลักสูตรผลิตออกมา
แต่ที่เผยแพร่ออกมามีเพียงฝั่งอุปสงค์

**Iris สร้างฝั่งอุปทานขึ้นมา** โดยอ่านเอกสาร มคอ.2 ของมหาวิทยาลัยไทย เชื่อมทุกรายวิชาเข้ากับ
คลังทักษะแห่งชาติ **พร้อมระบุระดับความชำนาญ** แล้วเปรียบเทียบโปรไฟล์หลักสูตรที่ได้กับ
อุปสงค์ที่เผยแพร่ไว้ของอาชีพใดก็ได้

ผลลัพธ์: รายงานการจับคู่ที่รู้ระดับ — *ทักษะใดที่อาชีพเป้าหมายต้องการแต่หลักสูตรไม่ได้พัฒนา
และทักษะใดที่พัฒนาไว้ตื้นเกินไป* — สืบย้อนกลับไปยังรายวิชาและหน้าเอกสารต้นทางได้

**ผลงานวิจัย:** การเชื่อมทักษะเชิงเอนทิตีที่รู้ระดับ (level-aware skill entity linking)
จากคำอธิบายรายวิชาภาษาไทยใน มคอ.2 ไปยังคลังคำศัพท์ควบคุมระดับชาติ ประเมินผลด้วยการกำกับ
โดยผู้เชี่ยวชาญ

## ทำไมจึงออกแบบใหม่

การออกแบบเดิมสร้างคลังทักษะของตัวเองด้วยการจัดกลุ่มคำที่สกัดจากเอกสาร และวัดอุปสงค์ด้วยการ
ดึงข้อมูลจากเว็บหางานไทยสี่แห่ง เดือนกรกฎาคม 2568 สป.อว. เผยแพร่มาตรฐานระดับชาติที่แทนที่
ทั้งสองอย่าง การเปลี่ยนทิศทางนี้ตัด scraper การจัดกลุ่ม ฐานข้อมูลเวกเตอร์ และคิวงานออกไป
พร้อมกับเพิ่มสิ่งที่การออกแบบเดิมทำไม่ได้: ทุกทักษะในมาตรฐานมี **สามระดับความชำนาญพร้อมเกณฑ์
ที่เขียนไว้ชัดเจน** และเอกสาร มคอ.2 ประกาศสัญญาณความลึกของตัวเองไว้ตามระเบียบ ทำให้วัดการ
จับคู่ได้ **ตามระดับ** ไม่ใช่เพียงว่ามีหรือไม่มี

ดู [`03-solution-design/solution-proposal.th.md`](03-solution-design/solution-proposal.th.md)

## สถาปัตยกรรม

สองส่วนที่ deploy แยกกัน เอนจินต้องใช้ GPU และใช้เวลาหลายสิบนาทีต่อรอบ ส่วนเว็บสาธารณะ
ต้องออนไลน์ตลอดไม่ว่าเอนจินจะเป็นอย่างไร

```
Internet ──► Cloudflare · vru-ai.com/iris
              │
              ├─ public   Astro static · ผลวิเคราะห์ที่เผยแพร่แล้ว · ไม่มี backend
              │
              └─ /app     Cloudflare Access (อาจารย์ในภาควิชา)
                            │ Cloudflare Tunnel (ออกทางเดียว)
                            ▼
                          gpu-linux-server · ห้องทำงานภาควิชา · 24/7
                            FastAPI · PostgreSQL · LLM ในเครื่อง
                            นำเข้า → เชื่อมทักษะ → ระดับ → จับคู่ → รายงาน → เผยแพร่
```

เอนจิน **เผยแพร่** เอกสารผลลัพธ์ที่มีเลขเวอร์ชัน ส่วนชั้นเว็บทำหน้าที่อ่านอย่างเดียว
ไม่มีอะไรบนเว็บสาธารณะที่แตะเครื่อง GPU ตอนมีคนเข้าใช้

## การตัดสินใจสำคัญ

| เรื่อง | ตัวเลือกที่เลือก | เหตุผล |
|---|---|---|
| คลังทักษะ | **มาตรฐานแห่งชาติ สแนปช็อตที่ตรึงไว้** | ทำซ้ำได้ เปรียบเทียบได้ และเป็นคลังที่ภาคส่วนกำลังรับมาใช้ |
| ข้อมูลอุปสงค์ | **ข้อมูลรัฐที่เผยแพร่แล้ว** — ไม่ scrape | ใครก็ทำซ้ำผลได้ และไม่มีความเสี่ยงด้านเงื่อนไขการใช้งาน |
| วิธีเชื่อมทักษะ | RAG — ดึงตัวเลือกมาก่อน แล้วให้ LLM ตัดสิน | นิยาม 4,376 รายการและเกณฑ์ระดับ 6,058 ข้อของมาตรฐาน *คือ* คลังสำหรับการค้นคืน |
| ระดับความชำนาญ | อนุมานจาก CLO, แผนที่ความรับผิดชอบ ● ○ และตำแหน่งในหลักสูตร | มคอ. ประกาศสัญญาณความลึกของตัวเอง ความขัดแย้งถูกรายงาน ไม่ถูกซ่อน |
| ตัวชี้วัดหลัก | ช่องว่างความครอบคลุมถ่วงน้ำหนักด้วยความชุก | ตัวเลขอุปสงค์เป็นความชุก ไม่ใช่การแจกแจง — ดูด้านล่าง |
| ฐานข้อมูลเวกเตอร์ | **ไม่ใช้** — เมทริกซ์ในหน่วยความจำ 13 MB | คลังคงที่ 4,376 รายการต้องการการค้นแบบตรง ไม่ใช่ดัชนีประมาณ |
| PDF ไทยที่เสียหาย | ด่านวินิจฉัย + การซ่อมกลิฟแบบกำหนดได้ | ความเสียหายเป็นการแทนที่ ไม่ใช่การหายไป — การซ่อมตรวจสอบย้อนได้ ต่างจาก OCR |
| ภาษาของเอนจิน | Python | การอ่าน PDF, NLP ภาษาไทย, การคำนวณ, เครื่องมือประเมินผล |
| เว็บ | Astro บน Cloudflare Workers | ตรงกับวิธีที่ `vru-ai-web` deploy อยู่แล้ว |

## ข้อจำกัดที่ทราบ

ระบุไว้ตั้งแต่ต้นเพราะเป็นตัวกำหนดว่าอ้างอะไรได้บ้าง

- **เวกเตอร์อุปสงค์ถูกตัดปลาย** ที่ประมาณ 100 ทักษะต่ออาชีพ การที่ทักษะหนึ่งไม่ปรากฏ
  แปลว่า *อยู่ต่ำกว่าเส้นตัด* ไม่ใช่ *ไม่เป็นที่ต้องการ*
- **`percentage` คือความชุก ไม่ใช่สัดส่วนของการแจกแจง** — เปอร์เซ็นต์ของอาชีพหนึ่งรวมกัน
  เกิน 100 ไปมาก ตัวชี้วัดเชิงการแจกแจงใด ๆ ต้องปรับมาตรฐานใหม่อย่างชัดแจ้งก่อน
- **ที่มาของคลังข้อมูลอุปสงค์ยังไม่ได้รับการยืนยัน** จำนวนประกาศงานอยู่ระหว่าง 203 ถึง 6.3 ล้าน
  ต่ออาชีพ ซึ่งไม่น่าเป็นไปได้หากเป็นข้อมูลไทยอย่างเดียว กำลังสอบถามกับ สป.อว./สจล.
  จนกว่าจะได้คำตอบ Iris ไม่อ้างว่าวัดตลาดแรงงาน *ไทย* โดยเฉพาะ
- **API ต้นทางยังเป็นรุ่นเบต้า** (`0.8.1-beta-public`) การวิเคราะห์ทุกครั้งรันบนสแนปช็อต
  ที่ตรึงไว้ ไม่เคยรันบน API สด

## สแนปช็อต

```bash
python3 data/skillmapping/fetch_snapshot.py                 # อุตสาหกรรมดิจิทัล
python3 data/skillmapping/fetch_snapshot.py --industry all
```

ใช้ stdlib อย่างเดียว เขียนสแนปช็อตที่ระบุวันที่และอธิบายตัวเองพร้อม manifest
สแนปช็อตที่ commit ไว้คือหลักยึดของการทำซ้ำ — การวิเคราะห์แต่ละครั้งบันทึกว่าใช้ตัวไหน
