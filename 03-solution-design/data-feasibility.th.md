### ตัวเลขอุปสงค์หมายถึงอะไรกันแน่

`percentage` คือ **ความชุก ไม่ใช่สัดส่วน** ภายในอาชีพหนึ่ง ค่า `count / percentage` คงที่
ดังนั้น `percentage = count / N × 100` โดย `N` คือจำนวนประกาศงานที่อยู่เบื้องหลังอาชีพนั้น
เปอร์เซ็นต์จึงรวมกันได้เกิน 100 ไปมาก (เฉลี่ย 1,358% สูงสุด 3,596%)

**เรื่องนี้สำคัญต่อตัวชี้วัดช่องว่าง** KL divergence ต้องการการแจกแจงความน่าจะเป็น การใช้มัน
จึงต้องปรับมาตรฐานเป็น `p_i = count_i / Σ count_j` ซึ่งเป็นปริมาณ *คนละอย่าง*
("สัดส่วนของการกล่าวถึงทักษะทั้งหมด") และต้องระบุการตีความนั้นอย่างชัดแจ้ง ความชุกเป็นสัญญาณ
ที่ตีความตรงกว่าสำหรับคณะกรรมการหลักสูตร: *"65% ของประกาศงานวิศวกรข้อมูลขอ SQL"* มีความหมาย
ต่อผู้บริหาร ส่วน *"SQL คิดเป็น 3.2% ของการกล่าวถึงทักษะ"* ไม่มีความหมาย

### ⚠️ ฝั่งอุปสงค์ไม่มีระดับความชำนาญ

ตรวจซ้ำเมื่อ 2026-08-28 รายการอาชีพ × ทักษะ มีเพียงสามฟิลด์พอดี

```json
{ "skill": { "id": "...", "title": "ทักษะการวิเคราะห์", "type": "soft-skill", ... },
  "count": 49415, "percentage": 15.48 }
```

**ไม่มีระดับ ไม่มีความอาวุโส ไม่มีฟิลด์ความชำนาญ** ใด ๆ ในฝั่งอุปสงค์ สามระดับที่มีนั้นเป็นของ
*ตัวทักษะเอง* — เป็นสเกลทั่วไปที่นิยามว่าพื้นฐาน/ปานกลาง/สูง หมายถึงอะไรสำหรับทักษะนั้น —
ไม่ใช่สิ่งที่อาชีพใดต้องการ

**ผลที่ตามมา:** ระดับมีอยู่ **เฉพาะฝั่งหลักสูตรเท่านั้น** Iris รายงานได้ว่า
*"หลักสูตรนี้พัฒนา SQL ถึงระดับสูง"* แต่รายงานไม่ได้ว่า *"ตลาดต้องการ SQL ระดับปานกลาง"*
เพราะตัวเลขนั้นไม่มีอยู่ ตัวชี้วัดใดที่นิยามเป็นส่วนต่างระหว่างระดับที่ตลาดต้องการกับระดับที่
หลักสูตรให้ จึงคำนวณไม่ได้ และประโยคใดที่สื่อเช่นนั้นคือการกุขึ้นมา

### ข้อจำกัดด้านคุณภาพข้อมูลที่ต้องเปิดเผย

1. **เวกเตอร์อุปสงค์ถูกตัดปลายที่ราว 100 ทักษะต่ออาชีพ** การแจกแจงมียอดที่ 92–98 และหยุดที่
   100 พอดี (2 อาชีพ) การที่ทักษะหนึ่งไม่ปรากฏในรายการของอาชีพหนึ่งจึง **ไม่ได้** แปลว่า
   ตลาดไม่ต้องการ แต่แปลว่ามันอยู่ต่ำกว่าเส้นตัด ข้ออ้างในรูป "ตลาดไม่ต้องการ X" จึงไม่มีอะไรรองรับ
2. **`N` ต่างกันถึงสี่ระดับเลขยกกำลัง** — ตั้งแต่ 203 ประกาศ (`information-technology-web-manager`)
   ถึง 6,291,725 (`software-engineer`) มัธยฐาน 25,740 ตัวเลข 6.3 ล้านประกาศสำหรับอาชีพเดียว
   ไม่น่าเป็นไปได้หากเป็นข้อมูลไทยล้วนและนับ ณ จุดเวลาเดียว **คลังข้อมูลเบื้องหลังน่าจะเป็นข้อมูล
   ระหว่างประเทศและ/หรือสะสมข้ามปี** ต้องขอความชัดเจนจาก สป.อว./สจล. ก่อนเขียนส่วนวิธีการ
   เพราะกระทบโดยตรงว่า Iris อ้างได้หรือไม่ว่าวัดความสอดคล้องกับตลาดแรงงาน *ไทย*
3. **168 คู่อาชีพ×ทักษะ (1.4%) มี `count = 0`** — ทักษะที่ระบุไว้กับอาชีพโดยไม่มีหลักฐานเลย
   รวมถึงข้อผิดพลาดที่เห็นชัด เช่น Python และ Pandas อยู่ที่ 0.00% สำหรับวิศวกรข้อมูล
   ต้องกรองแถวเหล่านี้ออก
4. **สามอาชีพว่างเปล่าโดยแท้จริง:** `security-solutions-architect` (0 ทักษะ),
   `character-modeler` (4), `senior-frontend-developer` (5) ให้ตัดออกหรือติดธง
5. **API ยังเป็นเบต้า** (`0.8.1-beta-public`) สแนปช็อตที่ตรึงไว้คือหลักยึดของการทำซ้ำ
   การวิเคราะห์ต้องบันทึกวันที่ของสแนปช็อต

ข้อความไทยจัดด้วย TH SarabunPSK ภายใต้การเข้ารหัส **WinAnsi** ซึ่งไม่มีจุดรหัสภาษาไทย
เครื่องหมายที่ซ้อนชั้นที่สองเหนือพยัญชนะจึงตกไปอยู่ในช่องกลิฟส่วนตัวของฟอนต์ที่ไม่มีรายการ
`ToUnicode` และถูกสกัดออกมาเป็นขยะ ASCII

**เอนจินสกัดข้อความสามตัวที่เป็นอิสระต่อกันให้ความเสียหายเหมือนกัน** — นี่อยู่ในไฟล์ PDF
ไม่ใช่ที่ตัวสกัด

| เอนจิน | ภาษาที่เขียน | เครื่องหมายไทยต่อ 1,000 อักขระไทย |
|---|---|---|
| poppler `pdftotext` | C++ | 134.5 |
| PyMuPDF / MuPDF | C | 134.5 |
| [xberg](https://github.com/xberg-io/xberg) 1.0.14 | Rust | 134.5 |
| *(ม.เกษตร ฐานอ้างอิงที่สะอาด)* | — | *171.0* |

ทั้งสามตัวคืน `ข-อมูลทั่วไป`, `ผลการเรียนรู2`, `ระบบฐานข2อมูล` เหมือนกัน เนื่องจากไม่มีตัวอ่านใด
กู้คืนการจับคู่ที่ไฟล์ PDF ไม่มีได้ เรื่องนี้จึงปิดคำถามว่าตัวสกัดที่ดีกว่าจะช่วยได้หรือไม่

⚠️ **ข้อค้นพบที่มีผลต่อการออกแบบโดยตรง** xberg รายงาน `quality_score: 1.0` และ
`extraction_method: native` บนเอกสารนี้ — คะแนนเต็มบนข้อความที่การันต์ถูกทำลายไป 99%
ตัวชี้วัดคุณภาพเอกสารทั่วไปไม่ได้จำลองความสมบูรณ์ของเครื่องหมายไทย
`VlmFallbackPolicy.on_low_quality` ของ xberg จึง **ไม่มีวันทำงาน** ในกรณีนี้ และข้อความ
ที่เสียหายจะผ่านเข้าสายงานไปอย่างเงียบ ๆ นโยบายสำรอง OCR อัตโนมัติใด ๆ ที่ Iris ใช้
ต้องขับเคลื่อนด้วยตัววินิจฉัยเฉพาะภาษาไทยด้านล่าง ไม่ใช่คะแนนคุณภาพทั่วไป

อัตราความเสียหายรายเครื่องหมาย วัดเทียบกับ ม.เกษตร เป็นฐานที่สะอาด (เครื่องหมายต่อ 1,000 อักขระไทย)

รวมเครื่องหมายทั้งหมดต่อ 1,000 อักขระไทย: ม.เกษตร 171.0, มศว 134.5, **มศว บวกการแทนที่
ที่ตรวจพบ 4,918 จุด ได้ 171.4** ความใกล้เคียงกับฐานที่สะอาดบ่งชี้ว่าแทบไม่มีอะไรสูญหาย —
เครื่องหมายยังอยู่ครบ เพียงแต่ใส่กลิฟผิดตัว ตารางซ่อมแบบกำหนดได้ที่ใช้คีย์
`(ตัวแทนที่, อักขระที่อยู่ก่อนหน้า)` ควรกู้ข้อความคืนได้ ส่วนต่างที่เหลือต้องตรวจสอบบนตัวอย่าง
ที่ใหญ่กว่านี้ก่อนจะอ้างว่าสมบูรณ์

**ม.เกษตร มีข้อบกพร่องคนละแบบ และการอ่านครั้งแรกผิด** `ำ` (สระอำ U+0E33) ปรากฏ
**ศูนย์ครั้ง** ใน 22,177 อักขระไทย เอกสารนี้เคยบันทึกว่าเป็นการยุบเหลือ `า` —
`คำอธิบาย` → `คาอธิบาย` — จึงถือว่าสูญข้อมูลและต้องใช้แบบจำลองภาพ

⚠️ **แก้ไขเมื่อ 2026-08-28 ระหว่าง Sprint 1** ข้อความจริงอ่านว่า `ค าอธิบาย`: มี **ช่องว่าง**
อยู่ตรงที่ `ำ` ควรอยู่ *ตำแหน่ง* ของเครื่องหมายยังคงอยู่ และการกู้คืนปลอดภัยด้วยหลักอักขรวิธี
ไม่ใช่สถิติ — `า` เป็นสระที่ต้องพึ่งพยัญชนะ ไม่สามารถขึ้นต้นพยางค์ได้ จึงเป็นไปไม่ได้ที่จะตามหลัง
ขอบเขตคำอย่างถูกต้อง ช่องว่างที่อยู่หน้า `า` เป็นสิ่งแปลกปลอมเสมอ **ม.เกษตร ไม่ต้องใช้
ทางสำรองด้วยภาพ** เพราะปรับให้เป็นปกติแล้วได้ชั้นข้อความที่สะอาด

การอ่านครั้งแรกมาจาก `pdftotext -layout` ซึ่งการเติมช่องว่างให้คอลัมน์ทำให้ `ค าอธิบาย`
อ่านเป็น `คาอธิบาย` การสกัดระดับอักขระแสดงช่องว่างนั้น ส่วน Adobe Acrobat แยกอักขระเดียวกัน
ด้วยวิธีที่ต่างออกไปอีก โดยเขียนเป็น `ํ` + `า` (ม.ศิลปากร 1,467 จุด) ซึ่งกู้คืนได้เช่นกันด้วยการประกอบ

**นัยสำคัญ:** **ด่านตรวจความสมบูรณ์ของชั้นข้อความ** แบบอัตโนมัติเป็นสิ่งจำเป็นก่อนเอกสารใด
จะเข้าสายงาน สถิติอัตราเครื่องหมายต่อ 1,000 อักขระไทยที่ใช้ข้างต้นคือตัววินิจฉัยนั้นเอง —
ต้นทุนต่ำ กำหนดผลได้แน่นอน และจับได้ทั้งสองรูปแบบความล้มเหลว

### ข้อค้นพบ B — สัญญาณ ELO สำหรับการอนุมานระดับมีอยู่จริง (ในเอกสาร มศว)

เอกสาร มศว มี **แผนที่แสดงการกระจายความรับผิดชอบมาตรฐานผลการเรียนรู้จากหลักสูตรสู่รายวิชา**
พร้อม ● ความรับผิดชอบหลัก / ○ ความรับผิดชอบรอง ต่อรายวิชา × ผลการเรียนรู้ **และ** มี CLO
รายวิชาและ MLO รายชุดวิชาที่จับคู่กับ ELO ของหลักสูตร

นั่นคือสัญญาณความลึกที่หลักสูตรประกาศเกี่ยวกับตัวเองภายใต้ระเบียบ มคอ. — เป็นฐานสำหรับ
อนุมาน `พื้นฐาน / ปานกลาง / สูง` ที่ดีกว่าการให้ LLM เดาจากคำอธิบายรายวิชามาก เมื่อรวมกับ
ชั้นปี (อนุมานจากรหัสวิชาได้) และสายวิชาบุรพวิชา จะได้แหล่งหลักฐานอิสระสามแหล่ง

**แต่ข้อความคัดมาของ ม.เกษตร ไม่มีส่วนนี้** ต้องได้เอกสาร มคอ.2 ฉบับเต็มของ ม.เกษตร
ก่อนจะประเมินการจับคู่ที่รู้ระดับบนหลักสูตรมากกว่าหนึ่งหลักสูตรได้

เนื่องจากคลังทักษะแห่งชาติเป็นสองภาษาโดยสมบูรณ์ คำอธิบายภาษาอังกฤษจึงจับคู่กับชื่อทักษะ

## ผลที่ตามมาต่อสถาปัตยกรรม

1. **การซ่อมกลิฟแบบกำหนดได้จัดการรูปแบบความล้มเหลวของ มศว ได้** — ตรวจสอบย้อนได้ ไม่มีค่าใช้จ่าย
   ทำซ้ำได้ และควรใช้ก่อนทุกครั้งที่ความเสียหายเป็นการแทนที่ ไม่ใช่การหายไป
   ⚠️ **แก้ไขเมื่อ 2026-08-28:** ข้อสรุปเดิมที่ว่า "ไม่ต้องใช้ OCR" ผิดในฐานะกฎทั่วไป
   การยุบ `ำ` ของ ม.เกษตร สูญข้อมูลจริง และการทบทวนวรรณกรรมพบแบบจำลองภาพภาษาไทยขนาด 3B
   ที่โฮสต์เองได้ ทำได้ถึง **ระยะ Levenshtein 0.04 บนแบบฟอร์มราชการไทย**
   ([[nonesung-2026-typhoon-ocr]]) ด่านตรวจจึงมี **สาม** ผลลัพธ์ — สะอาด / ซ่อมได้ /
   สูญข้อมูลหรือใช้ไม่ได้ → สกัดใหม่ด้วยภาพ พร้อมติดธงว่ามาจากภาพ
2. **ด่านตรวจความสมบูรณ์ของชั้นข้อความเป็นขั้นตอนชั้นหนึ่งของสายงาน** ไม่ใช่ของแถม
   เอกสารต้องถูกจำแนกเป็น `สะอาด / ซ่อมได้ / ใช้ไม่ได้` ก่อนนำเข้า
3. **ไม่มีเอนจินสกัดข้อความทั่วไปตัวใดแก้ปัญหานี้ได้** การประเมินเอนจินตัวที่สาม
   (xberg — แกน Rust รองรับ 106 รูปแบบ มี OCR เจ็ดตัวรวมตัวที่เป็น VLM) ให้ความเสียหาย
   เหมือนกันทุกไบต์และให้คะแนนคุณภาพเต็ม มันยังน่าสนใจในฐานะ *ชั้นจัดการ OCR* สำหรับ
   ทางสำรองด้วยภาพ — เพราะมีโซ่สำรอง เกณฑ์ความมั่นใจ และโมเดลเลย์เอาต์/ตาราง — แต่การสกัด
   ตารางของมันสืบทอดความเสียหายเดียวกันบนเส้นทางเนทีฟ (แผนที่ความรับผิดชอบหน้า 58 กลับมาเป็น
   เศษหัวตารางที่ไม่มีเครื่องหมาย ● ○ เลย เพราะเป็นกลิฟ Wingdings ที่ไม่มี `ToUnicode`)
   ให้ประเมินใน Sprint 1 แต่อย่ามอบหน้าที่ด่านตรวจให้มัน
4. **PageIndex เป็นเครื่องมือที่ถูกต้องสำหรับระบุตำแหน่งส่วนต่าง ๆ** ข้ามมหาวิทยาลัยที่จัดหน้า
   และจัดรูปแบบต่างกัน และโหนดที่พกช่วงหน้ามาให้การสืบย้อนรายข้อเท็จจริงที่รายงานวิชาการต้องการ
   ต้องใช้มันเพื่อ *ระบุตำแหน่ง* ของ `3.1.5 คำอธิบายรายวิชา` และตารางแผนที่ความรับผิดชอบ
   หลังจากนั้นจึงสกัดส่วนนั้น **ให้ครบถ้วน** — Iris ต้องการทั้ง ~78 รายวิชา ไม่ใช่ top-k
   ที่เกี่ยวข้องที่สุด
5. **ไม่จำเป็นต้องมีฐานข้อมูลเวกเตอร์** คลังทักษะคงที่ที่ 4,376 รายการ ที่ 768 มิติคือเมทริกซ์
   ในหน่วยความจำขนาด 13 MB และการคำนวณความคล้ายโคไซน์แบบตรงใช้เวลาระดับไมโครวินาที
   `pgvector` แก้ปัญหา — กลุ่มทักษะที่เกิดขึ้นเองแบบไม่จำกัด — ที่การเปลี่ยนทิศทางลบทิ้งไปแล้ว
6. **ตัวชี้วัดช่องว่างต้องอนุมานใหม่** จากความชุก ไม่ใช่จากการแจกแจงที่สมมติขึ้น และทุกข้ออ้าง
   ต้องเคารพการตัดปลายที่ราว 100 ทักษะ
