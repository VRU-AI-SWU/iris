## อะไรเปลี่ยนไป และทำไม

เดือนกรกฎาคม 2568 สำนักงานปลัดกระทรวง อว. (สป.อว.) เผยแพร่ฐานข้อมูล
**Thailand Skill Mapping** ที่พัฒนาโดย สจล. ซึ่งนิยามคลังคำศัพท์ **4,376 ทักษะ**
ในฐานะข้อมูลอ้างอิงระดับชาติ — แต่ละทักษะมีนิยามภาษาไทยและสามระดับความชำนาญ —
จับคู่กับ **371 อาชีพ** ใน 5 อุตสาหกรรมเป้าหมาย พร้อมตัวเลขอุปสงค์ติดมากับทุกคู่อาชีพ × ทักษะ

แพลตฟอร์มอธิบายจุดประสงค์ของตนเองว่าเป็นการเชื่อม **ฝั่งอุปสงค์** (ทักษะที่ตลาดแรงงานต้องการ)
เข้ากับ **ฝั่งอุปทาน** (สมรรถนะที่หลักสูตรผลิต) แต่ที่เผยแพร่มีเพียงฝั่งอุปสงค์
**ฝั่งอุปทานยังไม่ถูกสร้าง และนั่นคือสิ่งที่ Iris ทำพอดี**

เรื่องนี้เปลี่ยนกรอบของโครงการ Iris ไม่ใช่ระบบปิดที่คิดคลังทักษะของตัวเองแล้ววัดกับข้อมูล
ที่ดึงมาเองอีกต่อไป แต่เป็น **เอนจินฝั่งอุปทานของมาตรฐานแห่งชาติ** — ส่วนประกอบที่อ่านเอกสาร
มคอ.2 ของมหาวิทยาลัยไทย แล้วอธิบายหลักสูตรนั้นด้วยคำศัพท์ชุดเดียวกับที่รัฐใช้อธิบายอุปสงค์
ของตลาดแรงงานอยู่แล้ว

ผลที่ตามมามีมาก และส่วนใหญ่เป็นการตัดออก

| สิ่งที่ตัดออกจากการออกแบบ | เพราะ |
|---|---|
| Scraper สำหรับ JobThai, JobsDB, JOBBKK, JOBTOPGUN | ข้อมูลอุปสงค์เผยแพร่แล้วและรวมยอดมาแล้ว |
| การสร้างคลังทักษะที่เกิดขึ้นเอง (embedding + การจัดกลุ่ม HDBSCAN) | คลังคำศัพท์เป็นข้อมูลอ้างอิงระดับชาติที่คงที่ |
| Sidecar สำหรับจัดกลุ่มด้วย Python | ไม่เหลืออะไรให้จัดกลุ่ม |
| `pgvector` หรือฐานข้อมูลเวกเตอร์ใด ๆ | 4,376 รายการคงที่คือเมทริกซ์ในหน่วยความจำ 13 MB |
| คิวงานขนาดใหญ่ (Celery/Redis, Apalis) | มีไว้จัดการการดึงข้อมูลแบบขนาน |
| การจำแนก 20 บทบาทของ chaiaroon-2025 | แทนด้วย 138 อาชีพดิจิทัลอย่างเป็นทางการ |

และมีสิ่งที่เพิ่มเข้ามาหนึ่งอย่างที่ใหญ่: เพราะทุกทักษะในมาตรฐานมี **สามระดับความชำนาญ
พร้อมเกณฑ์ที่ระบุชัด** และเพราะเอกสาร มคอ. ประกาศสัญญาณความลึกของตัวเองภายใต้ระเบียบ
Iris จึงถามคำถามที่ไม่มีงานวิจัยใดเกี่ยวกับหลักสูตรไทยเคยถามได้ — ไม่ใช่
*"หลักสูตรนี้สอนทักษะ X หรือไม่"* แต่เป็น ***"สอนถึงระดับใด และเป็นระดับที่อาชีพนั้นต้องการหรือไม่"***

## คำอธิบายปัญหา

หลักสูตรไทยถูกบันทึกในรูปแบบ มคอ.2 ซึ่งระบุผลลัพธ์การเรียนรู้ที่ตั้งใจไว้ทั้งในรูปข้อความ
และในตารางแผนที่ความรับผิดชอบ ขณะที่รัฐเผยแพร่แล้วว่าแต่ละอาชีพต้องการทักษะใดบ้าง
ด้วยคลังคำศัพท์ควบคุม **แต่ไม่มีกลไกใดที่อธิบายหลักสูตรด้วยคำศัพท์ชุดเดียวกันนั้น**
สองครึ่งของความพยายามจัดทำแผนที่ทักษะระดับชาติจึงเปรียบเทียบกันไม่ได้ คณะกรรมการหลักสูตร
ที่กำลังปรับปรุงหลักสูตรจึงไม่มีคำตอบที่ทำซ้ำได้และมีหลักฐานรองรับสำหรับคำถามว่า
"ทักษะใดที่อาชีพเป้าหมายของเราต้องการแต่หลักสูตรนี้ไม่ได้พัฒนา และเราขาดที่ระดับใด"

## วิธีแก้ปัญหาที่เสนอ

Iris อ่านเอกสาร มคอ.2 สกัดทุกรายวิชาพร้อมคำอธิบาย น้ำหนักหน่วยกิต และความรับผิดชอบต่อ
ผลการเรียนรู้ที่ประกาศไว้ แล้ว **เชื่อมแต่ละรายวิชาเข้ากับคลังทักษะแห่งชาติพร้อมระบุระดับ
ความชำนาญ** การรวมข้ามรายวิชาให้ *โปรไฟล์ทักษะของหลักสูตร* ที่แสดงด้วยมาตรฐานแห่งชาติ
โดยตรง จากนั้นโปรไฟล์นั้นถูกเปรียบเทียบกับโปรไฟล์อุปสงค์ที่เผยแพร่ของอาชีพใดก็ได้ใน 138 อาชีพ
อุตสาหกรรมดิจิทัล ให้ผลเป็นรายงานการจับคู่ที่จัดลำดับความสำคัญ รู้ระดับ สืบย้อนถึงรายวิชา
และถึงหน้าในเอกสารต้นทางได้

**ผลงานวิจัยหลัก:** การเชื่อมทักษะเชิงเอนทิตีจากคำอธิบายรายวิชาภาษาไทยใน มคอ. ไปยัง
คลังคำศัพท์ควบคุมระดับชาติ **พร้อมระดับความชำนาญที่อนุมานได้ในฝั่งหลักสูตร** ประเมินผลด้วย
การกำกับข้อมูลโดยผู้เชี่ยวชาญ — และการวัดการจับคู่กับอุปสงค์ที่มาตรฐานเผยแพร่ รวมถึง
**ความชันตามระดับอาวุโส** ที่อนุมานจากอาชีพที่จับคู่ระดับต้น/ระดับอาวุโสไว้

> ⚠️ **ความแม่นยำของคำว่า "รู้ระดับ" ในที่นี้** มาตรฐานจัดระดับ *ทักษะ* ทุกตัวเป็นสามระดับ
> พร้อมเกณฑ์ แต่ **ไม่ได้** เผยแพร่ระดับที่ต้องการต่ออาชีพ × ทักษะ — รายการอุปสงค์ของอาชีพ
> มีเพียง `count` และ `percentage` ระดับจึงมีอยู่ **เฉพาะฝั่งหลักสูตรเท่านั้น** Iris พูดได้ว่า
> *"หลักสูตรนี้พัฒนา SQL ถึงระดับพื้นฐาน"* แต่พูดไม่ได้ว่า *"ตลาดต้องการ SQL ระดับปานกลาง"*
> และผลลัพธ์ใด ๆ ต้องไม่สื่อเป็นอย่างอื่น สัญญาณความลึกฝั่งอุปสงค์คือความชันตามระดับอาวุโส
> ที่อธิบายใน §5 ซึ่งอนุมานจากข้อมูลที่มีอยู่จริง

## กรณีการใช้งาน

### UC1 — รายงานการจับคู่หลักสูตรกับอาชีพ
- **ผู้กระทำ:** กรรมการหลักสูตร / ผู้บริหารวิชาการ
- **เงื่อนไขก่อนหน้า:** นำเข้าเอกสาร มคอ. แล้ว และเลือกอาชีพเป้าหมายจาก 138 อาชีพดิจิทัล
- **ลำดับ:** เลือกหลักสูตร → เลือกอาชีพ → ระบบเทียบโปรไฟล์ทักษะที่รู้ระดับของหลักสูตร
  กับอุปสงค์ที่เผยแพร่ของอาชีพนั้น → ได้รายงานการจับคู่ที่จัดอันดับ
- **ผลลัพธ์:** รายการ *ทักษะที่อาชีพต้องการแต่หลักสูตรไม่ได้พัฒนา* จัดอันดับด้วยความชุก
  และเมื่ออาชีพนั้นมีคู่ระดับอาวุโส จะมีแผงที่สองแสดง *ทักษะที่สำคัญขึ้นในขั้นอาวุโส และระดับที่
  หลักสูตรพัฒนาถึง* ทุกรายการสืบย้อนไปยังรายวิชาและหน้าใน มคอ.2 ต้นทางได้

### UC2 — การเปรียบเทียบหลักสูตรกับหลักสูตร
- **ผู้กระทำ:** คณะกรรมการหลักสูตร ผู้ประเมินคุณภาพ
- **เงื่อนไขก่อนหน้า:** นำเข้าทั้งสองหลักสูตรและตรวจการเชื่อมทักษะแล้ว
- **ลำดับ:** โปรไฟล์ทั้งสองแสดงด้วยคลังคำศัพท์แห่งชาติชุดเดียวกัน แล้วแยกเป็นสี่กลุ่ม —
  ร่วมกันที่ระดับเดียวกัน ร่วมกันแต่ *คนละระดับ* เฉพาะ A และเฉพาะ B
- **ผลลัพธ์:** โปรไฟล์ความแตกต่างที่เป็นภววิสัย นี่คือแรงจูงใจที่ภาควิชาระบุไว้สำหรับโครงการนี้
  คือการเทียบหลักสูตรของตัวเองกับของสถาบันอื่น
- **ข้อจำกัด:** หลักสูตรที่ยังไม่ผ่านการตรวจห้ามเข้าสู่การเปรียบเทียบ การเทียบโปรไฟล์ที่ตรวจแล้ว
  กับผลดิบของแบบจำลองจะทำให้ความผิดพลาดของการเชื่อมทักษะปรากฏเป็นความต่างของหลักสูตร
  ทั้งสองฝั่งต้องมีสถานะการตรวจเดียวกัน และรายงานต้องระบุสถานะนั้น
- ⚠️ **ส่งมอบในรุ่นแรกไม่ได้ตามสถานการณ์ปัจจุบัน** UC2 ต้องการหลักสูตรที่สมบูรณ์และผ่านการตรวจ
  *สองหลักสูตร* แต่มีเพียงเอกสาร มศว ที่สมบูรณ์ ส่วนไฟล์ ม.เกษตร เป็นข้อความคัดมา และการตรวจ
  แต่ละครั้งกินเวลาของอาจารย์ไปมาก ข้อจำกัดจึงอยู่ที่ความพร้อมของผู้ตรวจ ไม่ใช่กำลังประมวลผล
  UC2 ถูกสร้างใน Sprint 8 แต่ *สาธิต* ไม่ได้จนกว่าจะได้ มคอ.2 ฉบับเต็มฉบับที่สองมาและตรวจแล้ว —
  เป็นการพึ่งพาภายนอกที่มีมูลค่าสูงที่สุดของโครงการ

### UC3 — สถานการณ์การปรับปรุงหลักสูตร
- **ผู้กระทำ:** ผู้ออกแบบหลักสูตร ระหว่างรอบปรับปรุง มคอ.2
- **เงื่อนไขก่อนหน้า:** มีโปรไฟล์ฐานที่ผ่านการตรวจแล้ว
- **ลำดับ:** การแก้ไขสามแบบ ทั้งหมดคำนวณโปรไฟล์และการจับคู่ใหม่โดยไม่ต้องรัน LLM ซ้ำ —
  1. **รวมหรือตัดรายวิชา** (เอาวิชาเลือกเข้าหรือออก หรือยกเลิกรายวิชา)
  2. **ปรับการเชื่อมทักษะ** (รับ ปฏิเสธ หรือเปลี่ยนระดับ) ที่สืบทอดมาจากหน้าจอตรวจ
  3. **เพิ่มรายวิชาสมมติ** โดยวางคำอธิบายร่างเข้าไป ซึ่ง *จะ* เรียกการเชื่อมทักษะเฉพาะวิชานั้น
- **ผลลัพธ์:** ผลกระทบด้านทักษะของการเปลี่ยนแปลงที่เสนอ ก่อนจะลงมือจริง
- **ข้อจำกัด:** สถานการณ์สมมติไม่มีวันถูกเผยแพร่ เพราะเป็นหลักสูตรที่ยังไม่มีอยู่จริง
  การเผยแพร่จะเป็นการนำหลักสูตรที่ไม่มีอยู่ขึ้นเว็บสาธารณะ

### UC4 — โปรไฟล์หลักสูตรสาธารณะ
- **ผู้กระทำ:** ใครก็ได้ที่เข้า vru-ai.com
- **ลำดับ:** เรียกดูผลวิเคราะห์ที่เผยแพร่แล้ว — โปรไฟล์หลักสูตร แผนภาพความร้อน สรุปเชิงบรรยาย
- **ผลลัพธ์:** งานวิจัยอ่านได้และอ้างอิงได้โดยไม่ต้องมีบัญชี

*ตัดออกจากการออกแบบเดิม:* กรณีการใช้งาน "การจับคู่อาชีพสำหรับนักศึกษา" เพราะสื่อถึงคำแนะนำ

## วิธีการ

### 1. การนำเข้า พร้อมด่านตรวจความสมบูรณ์

เอกสาร มคอ. จริงที่ผลิตด้วยไดรเวอร์เครื่องพิมพ์สูญวรรณยุกต์และการันต์ไทยไปกับการเข้ารหัส
ฟอนต์ WinAnsi (วัดได้: การันต์คงเหลือ 1% ไม้โทคงเหลือ 14% ในเอกสาร มศว) ขณะที่เอกสารอื่น
ยุบ `ำ` เป็น `า` อย่างเงียบ ๆ ข้อบกพร่องทั้งสองมองไม่เห็นด้วยตัวแยกวิเคราะห์ธรรมดา และจะทำลาย
ทุกขั้นตอนถัดไป

เอกสารทุกฉบับจึงผ่าน **ด่านวินิจฉัย** ก่อนนำเข้า โดยดูอัตราเครื่องหมายประสมภาษาไทยต่อ
1,000 อักขระไทย เทียบกับฐานอ้างอิงของเอกสารที่สะอาด (~171) แล้วจำแนกเป็น

- **สะอาด** → ใช้ชั้นข้อความได้เลย
- **ซ่อมได้** → ใช้ตารางซ่อมกลิฟ รันด่านตรวจซ้ำ แล้วไปต่อเมื่อผ่าน
- **สูญข้อมูลหรือใช้ไม่ได้** → สกัดใหม่ด้วยแบบจำลองภาษาภาพภาษาไทย รันด่านตรวจซ้ำ
  และ **ติดธงว่าเอกสารนี้มาจากภาพ** ในข้อมูลที่มา

การซ่อมเป็นแบบกำหนดผลได้และตรวจสอบย้อนได้ — เป็นตารางที่ใช้คีย์จากกลิฟที่มาแทนกับอักขระ
ที่อยู่ก่อนหน้า — ไม่ใช่การเดาด้วย OCR หรือ LLM ตรงไหนที่ใช้ได้ สายงานจึงยังทำซ้ำได้ และ
อักขระที่ฟื้นคืนมาทุกตัวอธิบายที่มาได้ นั่นคือเหตุผลที่เลือกใช้ก่อน

**การปรับให้เป็นปกติ** ทำงานก่อน โดยย้อนการแตกเชิงโครงสร้างที่ไม่ต้องใช้ตารางที่เรียนรู้
เพราะอักขรวิธีไทยกำหนดคำตอบไว้แล้ว: `ำ` ที่เขียนเป็น `ํ` + `า` (Adobe) หรือเป็น
พยัญชนะ + ช่องว่าง + `า` (MS Word) เนื่องจาก `า` เป็นสระที่ต้องพึ่งพยัญชนะและขึ้นต้นพยางค์ไม่ได้
ช่องว่างที่อยู่หน้ามันจึงเป็นสิ่งแปลกปลอมเสมอ

จากห้ามหาวิทยาลัยและห้าผู้ผลิตไฟล์ PDF **ทุกเอกสารไปถึงชั้นข้อความที่ใช้งานได้โดยไม่ต้องใช้
แบบจำลองภาพ** (ดู `data-feasibility.th.md`) ทางสำรองด้วยภาพจึงยังคงอยู่เผื่อเอกสารที่จำเป็น
จริง ๆ — เอกสารสแกน หรือกรณีที่ข้อมูลหายไปแทนที่จะถูกแทนที่ — แต่ไม่ได้อยู่บนเส้นทางวิกฤต
อีกต่อไป และ **การนำเข้าไม่มีการพึ่งพา GPU** Typhoon OCR ทำได้ถึงระยะ Levenshtein 0.04
บนแบบฟอร์มราชการไทยที่ขนาด 3B พารามิเตอร์ โฮสต์ร่วมกับแบบจำลองที่ใช้ตัดสินได้ ธงระบุที่มา
สำคัญ เพราะการสกัดด้วยภาพเป็นผลลัพธ์ของแบบจำลอง ไม่ใช่การอ่านตามจริง ข้อค้นพบใดที่สืบย้อน
กลับไปหามันต้องระบุไว้ ด่านตรวจความสมบูรณ์ทำงานกับผลลัพธ์จากภาพด้วย — การสูญเครื่องหมายไทย
เป็นรูปแบบความล้มเหลวที่บันทึกไว้ของแบบจำลองภาพเช่นกัน — พร้อมกับการตรวจสัดส่วนอักขระไทย
เพื่อจับกรณีที่แบบจำลองเอนไปทางภาษาอังกฤษ

### 2. การนำทางในเอกสาร

มคอ.2 มีโครงสร้างส่วนที่ถูกกำกับด้วยระเบียบ แต่แต่ละมหาวิทยาลัยจัดหน้าและจัดรูปแบบต่างกัน
PageIndex สร้างดัชนีต้นไม้ของเอกสาร (จากเลย์เอาต์ของ PDF เอง พร้อมให้ LLM สรุปแต่ละโหนด)
และระบุตำแหน่งส่วนเป้าหมาย — `3.1.5 คำอธิบายรายวิชา` ตารางแผนที่ความรับผิดชอบ และรายการ
ELO ของหลักสูตร

มีข้อจำกัดสองข้อในการใช้

- **ระบุตำแหน่งก่อน แล้วสกัดให้ครบถ้วน** PageIndex เป็นระบบค้นคืน แต่ Iris ต้องการ
  *ทุก* รายวิชา ไม่ใช่วิชาที่เกี่ยวข้องที่สุด จึงใช้มันหาขอบเขตของส่วน แล้วจึงแยกวิเคราะห์ส่วนนั้นทั้งหมด
- **ที่มาเป็นสิ่งที่ต้องส่งมอบ** โหนดของต้นไม้พกช่วงหน้ามาด้วย คำอธิบายรายวิชาที่สกัดได้ทุกรายการ
  จึงบันทึกหน้าที่มันมาจาก ซึ่งจำเป็นทั้งสำหรับบทความและเพื่อให้คณะกรรมการหลักสูตรเชื่อถือข้อค้นพบ

### 3. การเชื่อมทักษะ

สำหรับแต่ละรายวิชา ระบบค้นคืนทักษะตัวเลือกจากคลัง 4,376 รายการ แล้วให้ LLM ในเครื่องตัดสิน
โดยเทียบกับนิยามของตัวเลือกเหล่านั้น

- **การค้นคืน** รวมความคล้ายเชิงหนาแน่น (เวกเตอร์ฝังตัวของชื่อทักษะ + นิยาม เก็บเป็นเมทริกซ์
  ในหน่วยความจำ 13 MB — คำนวณโคไซน์แบบตรง ไม่มีดัชนี ANN ไม่มีฐานข้อมูลเวกเตอร์)
  เข้ากับการจับคู่เชิงคำศัพท์ ซึ่งจำเป็นสำหรับชื่อเครื่องมือและคำศัพท์ภาษาอังกฤษ

  **สร้างเชิงคำศัพท์ก่อน และวัดผลแล้ว — Sprint 3** BM25 บนรูปผิวสามแบบต่อทักษะไม่ต้องใช้
  แบบจำลอง จึงไม่ต้องใช้ GPU และให้ค่าฐานก่อนที่โครงสร้างพื้นฐานการอนุมานใด ๆ จะมีอยู่
  วัดบนชุด *พัฒนา* 6 รายวิชาที่กำกับด้วยมือ (⚠️ ผู้กำกับคนเดียว ไม่มีค่าความสอดคล้อง —
  ใช้กำหนด `k` เท่านั้น ไม่ใช่หลักฐาน)

  | | @10 | @20 | @30 | @50 |
  |---|---|---|---|---|
  | BM25 รูปผิวสามแบบ | 67% | 67% | 75% | 75% |
  | **+ ช่องทางโครงพยัญชนะ** | **75%** | 75% | 75% | **83%** |

  ระยะห่างจาก 100% คือเหตุผลที่ต้องมีครึ่งเชิงหนาแน่น ไม่ใช่ข้อบกพร่องของครึ่งเชิงคำศัพท์:
  รายวิชาที่เขียนว่า `การสื่อสารข้อมูล` กับทักษะชื่อ `Network Architecture` ไม่มีโทเคนร่วมกันเลย
  ค่า `k = 30` ถูกใช้ต่อไป เพราะเป็นจุดที่ช่องทางเชิงคำศัพท์อิ่มตัว

  **ช่องทางที่สามที่การออกแบบไม่ได้คาดไว้: โครงพยัญชนะ** Sprint 2 จงใจไม่ซ่อมความเสียหาย
  ประเภทหนึ่ง — วรรณยุกต์ที่ถูกแทนด้วย *ช่องว่าง* — เพราะการเขียนทับเสี่ยงเปลี่ยนความหมาย
  (`ไม` ผ้าไหม กับ `ไม่` ปฏิเสธ) ผลที่วัดได้: `คพ231 เครือข่ายคอมพิวเตอร์` ค้นคืนได้
  *Storage Architecture, Rhinoceros, Elementary Education* แต่เมื่อซ่อมด้วยมือ ข้อความเดียวกัน
  ค้นคืนได้ *IT Networking, Computer Network Operations, Network Architecture*
  ความเสียหายที่หลงเหลือไม่ได้ทำให้การค้นคืนแย่ลง แต่ทำลายมัน การทำดัชนีชื่อทักษะไทย
  *ด้วยพยัญชนะของมันด้วย* — ทั้ง `เครือข่ายคอมพิวเตอร์` และ `เครือข ายคอมพิวเตอร=`
  ยุบเหลือ `ครอขยคอมพวตอร` เหมือนกัน — กู้การจับคู่คืนได้โดยไม่ต้องแตะเอกสาร ต้นทุนการชนกัน
  ที่วัดได้: 7.2% ของคลังมีโครงพยัญชนะซ้ำกับรายการอื่น ซึ่งยอมรับได้สำหรับขั้นตอนที่ผลลัพธ์
  จะถูกกรองด้วยการตัดสินอีกชั้น

- **ช่องทางสองภาษา เมื่อเอกสารมีให้** คลังคำศัพท์เป็นสองภาษาโดยสมบูรณ์ และเอกสาร มคอ. บางฉบับ
  ให้คำอธิบายภาษาอังกฤษทุกรายวิชา เมื่อมีทั้งคู่ การเชื่อมทักษะรันแยกกันบนแต่ละช่องทาง
  แล้วบันทึกความสอดคล้องเป็นสัญญาณความมั่นใจ
  ⚠️ **เป็นการตรวจสอบไขว้ ไม่ใช่ตาข่ายนิรภัย และเอกสารสองฉบับแสดงเหตุผล** ม.เกษตร
  ให้คำอธิบายภาษาอังกฤษครบทุกวิชาแต่เป็นกรณีที่ความเสียหาย *เบากว่า* ส่วน มศว เป็นภาษาไทยล้วน
  ในคำอธิบายรายวิชา (ภาษาอังกฤษปรากฏในชื่อวิชา) และเป็นกรณีที่ *รุนแรง* ช่องทางนี้จึงไม่มี
  ในเอกสารที่ต้องการมันมากที่สุด ต้องรายงานความครอบคลุมรายเอกสาร และการตัดสินใจออกแบบใด ๆ
  ห้ามสมมติว่ามีช่องทางนี้

- **แบบจำลอง และสองสิ่งที่การวัดสอนเรา (2026-08-31)**
  `iris-adjudicator` — `qwen3:8b` ที่ลงทะเบียนใหม่ผ่าน Modelfile ด้วย `num_ctx 8192`
  และ `temperature 0`

  ⚠️ **ขนาด context ไม่ใช่จำนวนพารามิเตอร์ คือสิ่งที่ตัดสินว่า Iris อยู่บน GPU ที่ใช้ร่วมกันได้ไหม**
  หน่วยความจำที่วัดได้ของแบบจำลอง 8B *ตัวเดียวกัน*: **32,768 ctx → 10.0 GB · 16,384 → 7.8 GB ·
  8,192 → 6.6 GB · 4,096 → 6.0 GB** prompt ของ Iris ยาวราว 2,650 โทเคน 8,192 จึงเหลือเฟือ
  และประหยัดได้ 3.4 GB เทียบกับค่าปริยายของ Ollama — เป็นส่วนต่างที่ทำให้รอบวิเคราะห์เดินต่อได้
  ขณะที่อีกโปรเจกต์ยึด 8.3 GB ไว้สำหรับ cross-validation ตั้งค่าที่ฝั่งเซิร์ฟเวอร์ใน Modelfile
  แทนที่จะส่งมากับแต่ละคำขอ เพราะ API ที่เข้ากันได้กับ OpenAI ไม่มีฟิลด์ `num_ctx` และเอนจิน
  ต้องพูดภาษานั้นต่อไป

  🔴 **แบบจำลองที่คิดก่อนตอบ คืนคำตอบว่าง ไม่ใช่คำตอบที่ผ่านการคิด** `qwen3` ใช้โควตาโทเคน
  ไปกับฟิลด์ `reasoning` ที่รูปแบบคำตอบของ OpenAI ไม่คืนมาเป็นเนื้อหา ทั้งหกรายวิชาในชุดพัฒนา
  จึงกลับมาเป็นสตริงว่างพร้อม `finish_reason: length` การตั้ง `reasoning_effort: "none"` แก้ได้
  ส่วน `think: false` และ `chat_template_kwargs.enable_thinking` ถูก Ollama เพิกเฉยอย่างเงียบ ๆ
  **เอนจินถือว่าคำตอบที่ถูกตัดกลางคันเป็นความล้มเหลว ไม่ใช่รายวิชาที่ไม่มีทักษะ** เพราะสัดส่วน
  รายวิชาที่ไม่มีทักษะเป็นสถิติความครอบคลุมที่การออกแบบนี้รายงาน และแบบจำลองที่โทเคนหมด
  ต้องไม่ไปสมทบกับสถิตินั้น

- **การตัดสินเป็นแบบเลือกตอบ ไม่ใช่การสร้างข้อความอิสระ** — *"ในทักษะตัวเลือก 30 รายการนี้
  รายวิชานี้พัฒนาทักษะใดบ้าง"* — ซึ่งง่ายกว่ามากสำหรับแบบจำลองขนาดเล็กในเครื่อง เมื่อเทียบกับ
  การสกัดแบบอิสระ และให้ผลลัพธ์ที่ถูกจำกัดให้เป็นรหัสทักษะที่ถูกต้องโดยโครงสร้าง
  ทุกการเชื่อมที่รับเข้ามาพก **ข้อความหลักฐาน** มาด้วย รูปแบบที่มีข้อจำกัดและผลิตหลักฐานนี้
  มีรายงานว่าทำได้ดีกว่าการสั่งแบบไม่จำกัด ไม่ใช่เพียงอธิบายได้ดีกว่า

- **ทักษะนอกคลังเป็นการตัดสินใจที่ระบุชัด ไม่ใช่เกณฑ์ความคล้าย** หลักสูตรสอนทฤษฎี ระเบียบวิธีวิจัย
  และจริยธรรม ที่ไม่มีประกาศงานใดอธิบาย การจับคู่สิ่งเหล่านั้นกับทักษะตลาดแรงงานที่ใกล้ที่สุด
  จะผิดอย่างมั่นใจ การสร้างแบบจำลองให้ "ไม่มีข้อใดถูก" เป็นผลลัพธ์ชั้นหนึ่งดีกว่าการใช้เกณฑ์ความคล้าย

  🔴 **ตัดสินรายทักษะ ไม่ใช่รายวิชา — วัดเมื่อ Sprint 3** จากการทดสอบหัวข้อวิชาแกน CS 18 หัวข้อ
  กับคลัง มี 7 หัวข้อที่ไม่มีรายการใดใช้ชื่อนั้น แต่มีสองเรื่องที่ต่างกันซ่อนอยู่หลังตัวเลขนั้น
  *วิศวกรรมซอฟต์แวร์* ไม่มีรายการ แต่คลังมีทักษะ `Software *` อยู่ 46 รายการ —
  `Requirements Analysis`, `Software Validation`, `Software Documentation`,
  `Software Quality Control` — ที่รายวิชานั้นพัฒนาอย่างชัดเจน ส่วน *สถาปัตยกรรมคอมพิวเตอร์*
  *คณิตศาสตร์ไม่ต่อเนื่อง* และ *สหกิจศึกษา* ไม่ปรากฏในทั้ง 4,376 รายการเลย แม้แต่ในนิยาม

  การประกาศว่าไม่มีในคลังจากชื่อรายวิชาจะรายงานกรณีแรกเป็นช่องว่างของหลักสูตรที่ไม่มีอยู่จริง
  ตัวเชื่อมทักษะจึงอ่าน **คำอธิบาย** แตกย่อย แล้วตัดสินเรื่องนอกคลังกับทักษะตัวเลือกแต่ละตัว
  หลังการแตกย่อย — เป็นกลไกที่ [[luyen-2025-skill-decomposition-ontology]] อธิบายไว้
  ส่วนตกค้างที่แท้จริงคือทฤษฎีและโครงสร้างหลักสูตร ซึ่งเป็นสิ่งที่ `q-out-of-vocabulary`
  ทำนายไว้บนหลักการ และตอนนี้ระบุได้บนการวัดจริง

- **ผู้ให้บริการแบบจำลองเป็นรอยต่อ ไม่ใช่ตัวเลือกที่ฝังตายตัว** การฝังตัวและการตัดสินรันหลัง
  ส่วนต่อประสานเดียวที่ไม่รู้จักผู้ให้บริการ โดยมีสองการติดตั้ง: endpoint ที่เข้ากันได้กับ OpenAI
  ในเครื่องบน `gpu-linux-server` และ **Cloudflare Workers AI** รูปแบบนี้นำมาจากโครงการ Argus
  ของแล็บ ซึ่งใช้งานจริงอยู่แล้ว

  สามเหตุผลที่มันเหมาะกับ Iris มากกว่าเหมาะกับ Argus

  | | Argus | Iris |
  |---|---|---|
  | ความอ่อนไหวของข้อมูล | ข้อมูลเวชระเบียน — **ห้ามออกจากเครื่อง** จึงต้องรันในเครื่องเป็นค่าปริยาย | เอกสาร มคอ. เป็น **เอกสารสาธารณะของสถาบัน** ไม่มีข้อจำกัดแบบนั้น |
  | รูปแบบการใช้งาน | เดโมเชิงโต้ตอบ ต้องการราว 32 เคส/วัน | ประมวลผลเป็นชุด ไม่กี่หลักสูตร **ต่อปี** |
  | ความเหมาะกับโควตาฟรี | เคยใช้โควตา 10,000 neurons/วัน จนหมดระหว่างพัฒนา | ≈ **$0.036 ต่อหลักสูตร** — ราวหนึ่งในสามของโควตาฟรีหนึ่งวัน |

  ยังช่วยลดความเสี่ยงที่บันทึกไว้ด้านล่าง: เมื่อโปรเจกต์อื่นของแล็บกำลัง train
  `gpu-linux-server` เหลือ VRAM ราว 15 GB แทนที่จะเป็น 23 GB และการเชื่อมทักษะรันบน
  Workers AI แทนการรอคิวได้

  **การนำเข้าเอกสารย้ายไม่ได้** การสกัดข้อความ PDF การนำทางด้วย PageIndex และทางสำรอง
  Typhoon OCR เป็นงานเนทีฟหรืองาน Python ที่ไม่มีสิ่งเทียบเท่าบน Workers รอยต่ออยู่ที่
  *การเชื่อมทักษะ* ไม่ใช่ที่ขอบของสายงาน

- 🔴 **ผู้ให้บริการถูกตรึงต่อรอบการวิเคราะห์ ไม่มีการสลับกลางรอบ** Argus สลับผู้ให้บริการกลางเคส
  และบันทึกว่าแบบจำลองใดอ่านหน้าไหน ซึ่งถูกต้องสำหรับเดโมแต่ผิดสำหรับที่นี่ หลักสูตรที่ 78 รายวิชา
  ถูกเชื่อมทักษะด้วยแบบจำลองสองตัวไม่ใช่การวิเคราะห์ที่ทำซ้ำได้ และเทียบกับหลักสูตรอื่นไม่ได้
  หากโควตาหมดกลางรอบ **รอบนั้นล้มเหลวและเข้าคิวใหม่บนผู้ให้บริการอีกรายตั้งแต่ต้น**
  ตาราง `analysis_run` บันทึกผู้ให้บริการควบคู่กับแบบจำลองและวันที่สแนปช็อต

  ผลพวงนี้ผูกกับการประเมินผล: **ด่าน Sprint 4 ต้องวัดผู้ให้บริการและแบบจำลองที่จะใช้จริง**
  การวัดแบบจำลองในเครื่องแล้วส่งมอบ Workers AI จะทำให้ทุกตัวเลขในบทความเป็นโมฆะ

- **ไม่ได้สมมติว่า LLM เป็นตัวจัดอันดับที่ดีที่สุด** การประเมินผลรวมค่าฐานจากตัวจัดอันดับ
  แบบมีผู้สอนไว้ด้วย เพราะมีอย่างน้อยหนึ่งงานวิจัยที่พบว่าแบบจำลองแบบมีผู้สอนชนะ LLM
  ในขั้นตอนนี้

- **รายวิชาหนึ่งอาจไม่เชื่อมกับอะไรเลยอย่างถูกต้อง** วิชาศึกษาทั่วไป — ภาษาไทย พลศึกษา จริยธรรม —
  พัฒนาความสามารถที่คลังตลาดแรงงานไม่ได้เรียกชื่อไว้ การไม่มีการเชื่อมเลยเป็นผลลัพธ์ที่ถูกต้อง
  และถูกบันทึก แยกออกจาก *ยังไม่ได้ประมวลผล* และ *ประมวลผลแล้วล้มเหลว* ในข้อมูล
  สัดส่วนรายวิชาที่ไม่มีการเชื่อมต่อหมวดเป็นสถิติที่รายงานได้และเป็นสัญญาณความครอบคลุม
  ของตัวมาตรฐานเอง ไม่ใช่ความผิดพลาดที่ต้องกลบ

#### ต้นทุนและเวลาที่ใช้

อนุมานจากสแนปช็อตที่ตรึงไว้ ไม่ใช่อ้างลอย ๆ: นิยามทักษะมีความยาวมัธยฐาน 149 อักขระ
ที่ `k = 30` ตัวเลือก prompt จึงพกบริบทของตัวเลือกราว 3,400 โทเคน บวกราว 270 สำหรับ
คำอธิบายรายวิชา และราว 300 สำหรับคำสั่ง — **≈ 3,970 โทเคนขาเข้าต่อรายวิชา** และ
**≈ 310,000 โทเคนขาเข้าต่อหลักสูตร** ที่มี 78 รายวิชาในภาษาเดียว เพิ่มเป็นสองเท่าเมื่อมี
ช่องทางสองภาษา ส่วนผลลัพธ์เป็นวัตถุที่มีโครงสร้างสั้น ๆ

**วัดจริงเมื่อ 2026-08-31 และค่าประมาณสูงเกินไปราว 50%** prompt จริงเฉลี่ย
**≈ 2,650 โทเคนขาเข้าต่อรายวิชา** (10,750 จากสี่รายวิชา, 15,932 จากหกรายวิชา) เพราะ
นิยามทักษะจำนวนมากสั้นกว่ามัธยฐานมาก และบางรายการไม่มีนิยาม ที่ **~4.2 วินาทีต่อรายวิชา**
บน `iris-adjudicator` หลักสูตร 78 รายวิชาจึงใช้เวลา **≈ 5–6 นาที และ ≈ 207,000 โทเคนขาเข้า** —
อยู่ในการคำนวณโควตาฟรีของ Workers AI ข้างต้นอย่างสบาย โดยมีระยะเผื่อ ไม่ใช่ปริ่ม

นั่นเป็นภาระที่พอประมาณสำหรับแบบจำลองที่ให้บริการในเครื่อง และไม่ใช่คอขวด ขั้นตอนฝั่งเอกสาร —
การสร้างต้นไม้ PageIndex บน 216 หน้า และการสกัดใหม่ด้วยภาพเมื่อด่านตรวจเรียกร้อง — เป็นตัวครอง
เวลาจริง คาดว่ารอบเต็มจะใช้เวลาระดับนาที ไม่ใช่หลายสิบนาที ตัวเลขจะวัดใน Sprint 10 ไม่ใช่
สัญญาไว้ตรงนี้ และส่วนติดต่อผู้ใช้ออกแบบเผื่อการรออยู่แล้ว

### 4. การอนุมานระดับ

ระดับความชำนาญอนุมานจากหลักฐานที่เอกสารมีอยู่แล้ว ไม่ใช่เดาจากคำอธิบายเพียงอย่างเดียว

1. **ผลการเรียนรู้รายวิชา (CLO)** เมื่อมี — จับคู่กับเกณฑ์ระดับของทักษะนั้นเองจากมาตรฐาน
2. **ตารางแผนที่ความรับผิดชอบ** — ● ความรับผิดชอบหลัก เทียบกับ ○ ความรับผิดชอบรอง
   เป็นการประกาศภายใต้ระเบียบของหลักสูตรเองว่าผลการเรียนรู้นั้นเป็นแกนของรายวิชาแค่ไหน
3. **ตำแหน่งในหลักสูตร** — ชั้นปีจากรหัสวิชา และความลึกของสายบุรพวิชา

เมื่อแหล่งข้อมูลขัดแย้งกัน ความขัดแย้งถูกบันทึกไว้แทนที่จะถูกตัดสินอย่างเงียบ ๆ อัตราความขัดแย้ง
เป็นข้อค้นพบที่รายงานได้ในตัวเอง

มีข้อจำกัดสองข้อจากวรรณกรรม ข้อแรก **ไม่ถาม LLM เรื่องระดับแบบองค์รวม** เพราะการจำแนก
ผลการเรียนรู้เข้าระดับ Bloom ด้วย LLM แบบ zero-shot วัดได้ 0.72–0.73 ตามหลังตัวจำแนกแบบดั้งเดิม
ที่ใช้ลักษณะจากคำกริยาบนข้อมูลชุดเดียวกันกว่ายี่สิบจุด ค่าฐานที่ไม่ใช้ LLM บนข้อความ CLO
จึงเป็นส่วนหนึ่งของการประเมินผล และอาจชนะ ข้อสอง **แผนที่ ● / ○ เป็นหลักฐาน ไม่ใช่มาตรฐานทอง** —
มันถูกเขียนด้วยมือเพื่อการรับรองคุณภาพ และการสร้างมันขึ้นใหม่อัตโนมัติทำได้เพียง 83–88%
เมื่อเทียบกับผู้เชี่ยวชาญ โดยต่างกัน 5 จุดระหว่างสองหลักสูตรในสถาบันเดียวกัน ความแปรปรวนนั้น
ยังเป็นข้อควรระวังสำหรับการเปรียบเทียบข้ามสถาบันด้วย

### 5. การวัดการจับคู่

ตัวเลขอุปสงค์ที่เผยแพร่คือ **ความชุก** — สัดส่วนของประกาศงานของอาชีพหนึ่งที่เอ่ยถึงทักษะหนึ่ง —
ไม่ใช่การแจกแจงความน่าจะเป็น เปอร์เซ็นต์ของอาชีพหนึ่งรวมกันเกิน 100 ไปมาก และดังที่ระบุข้างต้น
**มันไม่มีระดับ** ตัวชี้วัดจึงนิยามบนสิ่งที่ข้อมูลมีอยู่จริง

#### โปรไฟล์หลักสูตร

การรวมการเชื่อมทักษะระดับรายวิชาขึ้นเป็นโปรไฟล์หลักสูตร สำหรับแต่ละทักษะ *s*

| องค์ประกอบ | นิยาม |
|---|---|
| `covered` | มีอย่างน้อยหนึ่งรายวิชาเชื่อมกับ *s* หลังผ่านการตรวจ |
| `level` | **ค่าสูงสุด** จากรายวิชาที่เชื่อม — หลักสูตรพัฒนาทักษะถึงระดับที่ลึกที่สุดที่รายวิชาใดไปถึง |
| `depth` | จำนวนรายวิชาที่เชื่อม และหน่วยกิตรวมของรายวิชาเหล่านั้น |
| `sources` | ตัวรายวิชาเอง เพื่อการสืบย้อน |

ใช้ **ค่าสูงสุด** ไม่ใช่ค่าเฉลี่ยถ่วงน้ำหนักสำหรับระดับ เพราะความสามารถของหลักสูตรถูกกำหนดโดย
การสอนที่ก้าวหน้าที่สุด ไม่ใช่ค่าเฉลี่ยที่ถูกเจือจางด้วยการกล่าวถึงระดับเบื้องต้น การถ่วงน้ำหนัก
หน่วยกิตเข้าที่ `depth` ไม่ใช่ `level` — หลักสูตรทุ่มเวลาให้ทักษะหนึ่งเท่าไร เป็นคนละคำถามกับ
สอนทักษะนั้นลึกแค่ไหน ดู [[q-credit-weighting]]

#### ตัวชี้วัดหลัก — ช่องว่างความครอบคลุมถ่วงน้ำหนักด้วยความชุก

สำหรับอาชีพเป้าหมาย ให้จัดอันดับทักษะที่อาชีพนั้นต้องการแต่หลักสูตรไม่ได้พัฒนา
โดยถ่วงน้ำหนักด้วยความชุก

> *"65% ของประกาศงานวิศวกรข้อมูลเอ่ยถึง SQL — หลักสูตรพัฒนาทักษะนี้ (ระดับสูง, คพ242)
> 58% เอ่ยถึงคลังข้อมูล — ไม่มีรายวิชาใดพัฒนาทักษะนี้"*

ทุกพจน์วัดได้ ไม่มีข้ออ้างใดเกี่ยวกับระดับที่ตลาดต้องการ

#### การถ่วงน้ำหนักความเฉพาะเจาะจงต่ออาชีพ (RCA)

ลดน้ำหนักทักษะที่ทุกอาชีพต้องการ และเพิ่มน้ำหนักทักษะที่แยกแยะอาชีพ เพื่อให้รายการที่จัดอันดับ
นำไปใช้ได้จริง แทนที่จะถูกครอบงำด้วยทักษะทางสังคมที่มีอยู่ทุกที่

⚠️ **ต้องระบุตัวส่วน เพราะการเลือกตัวส่วนเปลี่ยนอันดับ** RCA เป็นอัตราส่วนของสัดส่วน ตัวเศษ —
สัดส่วนของทักษะภายในอาชีพ — เหมือนกันไม่ว่าจะคำนวณจาก `count` หรือ `percentage` เพราะ `N_c`
ตัดกัน แต่ตัวส่วน *ระดับโลก* ไม่เหมือนกัน: การถ่วงน้ำหนักอาชีพด้วยปริมาณประกาศงานให้คำตอบ
ต่างจากการนับแต่ละอาชีพเป็นหนึ่งหน่วยสังเกต วัดบนวิศวกรข้อมูลได้มัธยฐาน |ΔRCA| = 3.02
สูงสุด 23.86 และ **อันดับ 15 อันดับแรกซ้อนทับกันเพียง 8 จาก 15**

**Iris ใช้การถ่วงน้ำหนักแบบให้ทุกอาชีพเท่ากัน** การถ่วงด้วยจำนวนสืบทอดความหมายของ `N`
ที่ยังไม่ได้ข้อยุติ (203 ถึง 6,291,725 ต่ออาชีพ) หากช่วงนั้นเป็นสิ่งแปลกปลอมจากคลังข้อมูล
การถ่วงด้วยจำนวนจะส่งต่อความผิดพลาดนั้นเข้าไปในทุกรายการที่จัดอันดับ ทางเลือกนี้ถูกระบุใน
ผลลัพธ์ทุกชิ้น และรายงานทางเลือกอีกแบบเป็นการตรวจความไว ดู [[q-prevalence-metrics]]

#### ความชันตามระดับอาวุโส — สัญญาณความลึกฝั่งอุปสงค์

มาตรฐานมี **13 อาชีพที่จับคู่ตามระดับอาวุโส** ในอุตสาหกรรมดิจิทัล ซึ่ง **วิเคราะห์ได้ 12 คู่** —
`senior-frontend-developer` มีเพียง 5 ทักษะ และถูกตัดออกด้วยตัวกรองอาชีพที่ข้อมูลไม่สมบูรณ์
(ตรวจสอบในโค้ดแล้ว Sprint 0): `data-scientist` มีสี่ขั้น (ฐาน → อาวุโส → หัวหน้า → ประธาน)
ส่วน `data-engineer`, `web-developer`, `developer`, `application-developer` และ
`sound-designer` มีฐาน → อาวุโส `project-manager` และ `animator` มีฐาน → หัวหน้า
และ `software-engineer` มีระดับต้น → ฐาน

สำหรับอาชีพที่จับคู่ไว้ การเปลี่ยนแปลงของความชุกระหว่างขั้นเป็นสัญญาณที่วัดได้ว่าทักษะใด
กลายเป็นแกนกลางมากขึ้นตามประสบการณ์ สำหรับนักวิทยาการข้อมูล → นักวิทยาการข้อมูลอาวุโส

| Δ ความชุก | ทักษะ |
|---|---|
| **+12.67 pp** | การสร้างแบบจำลองทำนาย |
| **+12.02 pp** | การประยุกต์ใช้การเรียนรู้ของเครื่อง |
| **+10.49 pp** | สถิติเชิงพหุ |
| +2.24 pp | จาวา |
| −0.58 pp | ทักษะการวิเคราะห์ |

การไขว้ข้อมูลนี้กับระดับของหลักสูตรเองให้ข้อค้นพบที่แข็งแรงที่สุดของรายงาน

> *"ทักษะที่ขึ้นมากที่สุดจากนักวิทยาการข้อมูลไปเป็นนักวิทยาการข้อมูลอาวุโส — การสร้างแบบจำลอง
> ทำนาย การประยุกต์ใช้การเรียนรู้ของเครื่อง และสถิติเชิงพหุ — หลักสูตรนี้พัฒนาไว้เพียงระดับพื้นฐาน"*

นี่ **ไม่ใช่** ข้อกำหนดความชำนาญ และต้องไม่นำเสนอเป็นเช่นนั้นเด็ดขาด มันเป็นข้อความเกี่ยวกับ
ทักษะที่สำคัญขึ้นตามระดับอาวุโส ซึ่งเป็นคำถามที่คณะกรรมการหลักสูตรลงมือได้:
*เรากำลังเตรียมบัณฑิตสำหรับตำแหน่งแรกเข้า หรือสำหรับทั้งเส้นทางอาชีพ*

ข้อจำกัดอยู่ที่ความพร้อมของข้อมูล — มีขั้นบันไดที่วิเคราะห์ได้ 12 ขั้นจาก 138 อาชีพดิจิทัล
แกนนี้จึงมีสำหรับอาชีพเป้าหมายบางอาชีพและไม่มีสำหรับอาชีพอื่น รายงานต้องระบุว่ากรณีใด

บันไดทั้งหมด พร้อมทักษะที่ขึ้นสูงสุดที่วัดบนสแนปช็อตที่ตรึงไว้

## การประเมินผล

ด่านประเมินผลกำกับทั้งโครงการ: **ไม่มีคุณสมบัติใดที่ผู้ใช้เห็นถูกสร้างก่อนที่คุณภาพการเชื่อมทักษะ
จะถูกวัด** นี่คือวินัยที่ระยะก่อนหน้าประกาศไว้แล้วไม่ทำตาม และเป็นเหตุที่ระยะนั้นหยุดชะงัก

**⚠️ ด่านต้องวัดระบบที่ผลิตผลลัพธ์จริง ไม่ใช่แบบจำลองเพียงลำพัง** สิ่งที่ Iris ส่งมอบคือการเชื่อม
ทักษะที่ **ผ่านการตรวจ** ไม่ใช่ผลดิบของแบบจำลอง นั่นคือเหตุผลทั้งหมดของหน้าจอตรวจ แต่การ
ประเมินความแม่นยำและความครบถ้วนของแบบจำลองไม่ได้บอกอะไรเลยเกี่ยวกับคุณภาพของสิ่งที่ผู้ตรวจ
ผลิตออกมาจริง และมีหลักฐานว่าเรื่องนี้สมมติเอาไม่ได้: คู่มนุษย์–AI มักทำได้แย่กว่า AI เดี่ยว ๆ
ภายใต้อคติเชื่อระบบอัตโนมัติ ด่านที่ผ่านด้วยค่า F1 ของแบบจำลองจะอนุญาตให้สร้างทุกอย่างถัดจากนั้น
บนสมมติฐานที่ไม่เคยทดสอบ และหน้าจอเองจะไม่ถูกตรวจสอบจนถึง Sprint 9 — หลังจากทั้งการออกแบบ
ผูกติดกับมันไปแล้ว

### 🔴 สิ่งที่ Sprint 3 พิสูจน์ว่าด่านนี้ต้องป้องกัน

Sprint 3 สร้างชุดพัฒนา 6 รายวิชาไว้กำหนดค่า `k` ใช้วัดความครบถ้วนได้ตามที่ตั้งใจ
แต่เมื่อใช้วัด **ความแม่นยำ มันให้ตัวเลขที่ผิดล้วน ๆ** และวิธีที่มันผิดคือสเปกของโปรโตคอล
การกำกับข้อมูล

การให้คะแนน `iris-adjudicator` เทียบกับป้ายเหล่านั้นได้ความแม่นยำ 23% แต่การอ่านตัวบท
ต้นทางแสดงว่าแบบจำลองถูกและป้ายแคบเกินไป: คำอธิบายของ คพ231 เขียนว่า
*โปรโตคอลการหาเส้นทางแบบสถิตและพลวัต* ดังนั้น `routing-protocols`, `communication-protocols`
และ `data-networks` ที่แบบจำลองเลือกล้วนถูกต้องตามตัวบท แต่ไม่มีในชุดทองที่มีเพียง
`computer-networking` ส่วน คพ251 เขียนว่า *การออกแบบและการสร้างเว็บแอปพลิเคชัน* และ
`web-application-design` ถูกนับเป็นผลบวกลวง นี่คือกับดัก single-gold ที่
[[zhang-2024-job-market-entity-linking]] รายงานไว้พอดี

**สามข้อกำหนดที่ตามมา และไม่มีข้อใดเป็นทางเลือก**

1. **ป้ายกำกับมาจากการอ่านตัวบทคำอธิบายให้ครบ ไม่ใช่จากความรู้สึกของผู้ตรวจว่ารายวิชานี้
   "เกี่ยวกับอะไร"** รายวิชาหนึ่งเอ่ยถึงทักษะมากกว่าที่ชื่อของมันบอก
2. **ป้ายกำกับถูกปิดก่อนเห็นผลลัพธ์ของแบบจำลองใด ๆ** การขยายชุดทองหลังอ่านคำทำนาย
   เปลี่ยนการวัดให้กลายเป็นภาพเหมือนตัวเอง
3. **อนุญาตให้มีการเชื่อมที่ถูกต้องหลายรายการต่อวิชาและให้คะแนนเช่นนั้น** — ซึ่งเป็นเหตุผล
   ที่ค่าความสอดคล้องใช้ Krippendorff's α กับระยะ MASI ไม่ใช่ κ

ห้ามรายงานตัวเลขความแม่นยำใด ๆ ก่อนผ่านด่าน ตัวเลขความครบถ้วนของ Sprint 3 ยังใช้ได้
ส่วนตัวเลขความแม่นยำถูกถอน

ครึ่งที่เป็นระบบรันบน **ส่วนติดต่อผู้ใช้ขั้นต่ำ** — สเปรดชีตหรือ CLI ไม่ใช่หน้าจอของ Sprint 9 —

- **คุณภาพหลังผ่านการตรวจ** — วัดผลที่ผ่านการตรวจเทียบกับมาตรฐานทอง หากไม่ดีกว่าผลดิบของ
  แบบจำลอง แสดงว่าสมมติฐานเรื่องการตรวจผิด และต้องเปลี่ยนการออกแบบ ไม่ใช่ส่วนติดต่อผู้ใช้
- **ปริมาณงานต่อเวลา** — จำนวนการตัดสินใจต่อชั่วโมง ประมาณการไปยังหลักสูตร 78 รายวิชา
  การตรวจทุกการเชื่อมคือ 624–1,092 การตัดสินใจ หรือ 104–182 นาทีที่ 10 วินาทีต่อครั้ง
  เป้าหมาย 90 นาทีไปถึงได้เฉพาะเมื่อรับทีเดียวโดยดูความมั่นใจ ซึ่งทำให้ตัวเลขถัดไปสำคัญมาก
- **การปรับเทียบความมั่นใจ** — การเชื่อมที่ความมั่นใจสูงถูกต้องใกล้เคียงกับค่าที่ระบุหรือไม่
  หากราว 70% ของการเชื่อมถูกรับโดยไม่ตรวจทีละรายการ คะแนนที่ไม่ได้ปรับเทียบคือช่องทาง
  ให้ความผิดพลาดที่มั่นใจเข้าไปในรายงานที่เผยแพร่

**"เพียงพอ" หมายถึงอะไร** งานวิจัยอิสระสี่ชิ้นวางค่า top-1 แบบเข้มงวดสำหรับการเชื่อมทักษะกับ
คลังอาชีพขนาดใหญ่ไว้ที่ **0.23–0.29** และคะแนนทั้งสายงานราว **0.56** — และทุกชิ้นรายงานว่า
การจัดอันดับดีกว่าการเลือกมาก (Acc@32 ราวสองเท่าของ Acc@1; MRR 0.82 เทียบกับ F1 0.57)
Iris มีเหตุให้คาดหวังผลที่ดีกว่า ด้วยพื้นที่ตัวเลือกที่เล็กกว่าสามเท่าและใช้คำอธิบายรายวิชาทั้งชิ้น
แทนที่จะเป็นช่วงข้อความจากประกาศงาน แต่ต้องไม่นำเสนอตัวเลขของตนว่าเทียบเคียงกับของพวกเขาได้
**ผลที่ตามมาคือ หน้าจอตรวจโดยมนุษย์เป็นข้อกำหนดของวิธีการ ไม่ใช่ความสะดวก: ที่ระดับความแม่นยำ

| **การแย่ง GPU กับโปรเจกต์อื่นของแล็บ วัดเป็นวันไม่ใช่ชั่วโมง** `gpu-linux-server` ใช้ร่วมกัน โปรเจกต์ Prostate MRI train แบบ 5-fold cross-validation ที่ราว 30 ชม./fold — **ราว 150 ชม. ต่อรอบเต็ม** — ยึด 7.8 GB จากการ์ด 24 GB ตลอดเวลา เหลือ 15.4 GB แต่ละ fold รันทีละอันเพื่อให้สลับกันได้ ช่วงที่พึ่งพาได้จึงอยู่ *ระหว่าง* fold ส่วนเดสก์ท็อปและ X11 ยึดอีกราว 1.2 GB ถาวร | สูง — เป็นสภาวะปกติ ไม่ใช่เหตุการณ์ผิดปกติ | **สูง** | กำหนดขนาดหน่วยความจำแบบจำลองสำหรับกรณี **ที่มีการแย่ง** (~15 GB) ไม่ใช่กรณีว่าง เพื่อไม่ให้การวิเคราะห์ล้มเหลวอย่างคาดเดาไม่ได้เมื่อโปรเจกต์อื่นเริ่ม train ตั้ง `OLLAMA_KEEP_ALIVE` อย่างชัดแจ้งเพื่อให้แบบจำลองคืน VRAM ระหว่างรอบ ตรวจ VRAM ว่างก่อนเริ่มแล้วเข้าคิวแทนที่จะล้มเหลว และ Sprint 1–2 ไม่ต้องใช้ GPU เลย งานนำเข้าจึงเดินหน้าได้ตลอด |

## ทางเลือกอื่นที่พิจารณาแล้ว

| ทางเลือก | ทำไมไม่เลือก |
|---|---|
| ใช้คลังทักษะที่เกิดขึ้นเองจากการจัดกลุ่มต่อไป | ไม่เสถียรข้ามรอบ ไม่มีมาตรฐานทอง และตอนนี้เข้ากันไม่ได้กับมาตรฐานแห่งชาติที่ภาคส่วนกำลังรับมาใช้ |
| ดึงประกาศงานต่อไป | ซ้ำซ้อนกับข้อมูลรัฐที่เผยแพร่แล้ว เสี่ยงเรื่องเงื่อนไขการใช้งาน และให้ผลที่ไม่มีใครทำซ้ำได้ |
| ใช้ฐานข้อมูลเวกเตอร์ (pgvector, Qdrant) สำหรับค้นคืนทักษะ | เวกเตอร์คงที่ 4,376 ตัวอยู่ในหน่วยความจำ 13 MB การค้นแบบตรงใช้เวลาไมโครวินาที ฐานข้อมูลเวกเตอร์แก้ปัญหาการขยายขนาดที่การออกแบบนี้ไม่มี |
| ใช้การสกัดด้วยภาพเป็นเส้นทาง *ปริยาย* สำหรับ PDF ภาษาไทย | เมื่อความเสียหายเป็นการแทนที่กลิฟ การซ่อมแบบกำหนดได้กู้ข้อความคืนได้ตรงเป๊ะ ไม่มีค่าใช้จ่าย และตรวจสอบย้อนได้ ซึ่งเป็นคุณสมบัติที่ผลลัพธ์ของแบบจำลองให้ไม่ได้ การใช้ภาพเป็น **ทางสำรอง** สำหรับชั้นข้อความที่สูญข้อมูลหรือใช้ไม่ได้ ไม่ใช่ค่าปริยาย (§1) |
| ใช้เอนจินสกัดข้อความตัวอื่น | poppler, PyMuPDF และ xberg ให้ความเสียหายเหมือนกันทุกไบต์บนเอกสาร มศว (134.5 เครื่องหมายต่อ 1,000 อักขระไทยเท่ากันทั้งสาม) ข้อบกพร่องคือ `ToUnicode` ที่ขาดหายในไฟล์ PDF ไม่มีตัวอ่านใดกู้สิ่งที่ไม่มีอยู่ได้ |
| มอบการตัดสินเรื่องความสมบูรณ์ให้คะแนนคุณภาพของเอนจินเอกสารเอง | xberg รายงาน `quality_score: 1.0` บนเอกสารที่การันต์ถูกทำลาย 99% ตัวชี้วัดคุณภาพทั่วไปไม่ได้จำลองความสมบูรณ์ของเครื่องหมายไทย ทางสำรองอัตโนมัติเมื่อคุณภาพต่ำจึงไม่มีวันทำงาน |
| เก็บ backend ที่เป็น Rust ไว้ | ข้อได้เปรียบด้านการทำงานพร้อมกันของมันมีไว้สำหรับการดึงข้อมูล งานที่เหลือคือการอ่าน PDF, NLP ภาษาไทย, การคำนวณ และเครื่องมือประเมินผล ซึ่งเป็น Python ทั้งหมด และแกน Rust จะต้องมี sidecar Python อยู่ดี |
| รันเอนจินบน CSML | GPU ของ CSML ถูกแย่งใช้ทั้งภาควิชาและความพร้อมใช้อยู่นอกการควบคุมของโครงการ ส่วน `gpu-linux-server` **ก็ไม่ได้เป็นของโครงการแต่ผู้เดียวเช่นกัน** — ใช้ร่วมกับโปรเจกต์อื่นของแล็บ — แต่การแย่งนั้น *จัดตารางกันเองได้*: คนกลุ่มเดียวกันเป็นผู้ตัดสินว่าอะไรรันเมื่อไร นั่นคือความต่างที่แท้จริง และมันเล็กกว่าคำว่า "เครื่องเฉพาะ" จะสื่อ |
| เปิด API วิเคราะห์สู่สาธารณะ | การเปิดให้เข้าถึง GPU โดยไม่ยืนยันตัวตนเสี่ยงต่อการถูกใช้ในทางที่ผิด และอาจารย์ในภาควิชาเป็นผู้ใช้กลุ่มเดียวที่ตั้งใจไว้ในระยะนี้ |
| ใช้ Next.js สำหรับชั้นเว็บ | ชั้นสาธารณะเป็นการแสดงข้อมูล เครื่องจักรของ OpenNext ไม่คุ้ม ส่วน Astro ตรงกับการ deploy แบบ static-assets-on-Workers ที่เว็บแล็บใช้อยู่แล้ว |

## คำถามที่ยังเปิดอยู่

บล็อกการเขียนส่วนวิธีการ

- จำนวนอุปสงค์มาจากคลังข้อมูลใด — ไทยหรือระหว่างประเทศ ช่วงเวลาใด `N` เป็นค่าสะสมหรือไม่
  *(ภายนอก — สป.อว. / สจล.)*
- เพดานราว 100 ทักษะเป็นข้อจำกัดของการแสดงผลหรือของข้อมูล และขอเวกเตอร์เต็มเพื่อการวิจัย
  ได้หรือไม่ *(ภายนอก)*

เชิงประจักษ์ ตอบได้ระหว่างการพัฒนา

- ตารางซ่อมกลิฟใช้ได้ทั่วไปข้ามผู้ผลิตไฟล์ PDF หรือไม่
- ความลึกของการค้นคืน `k` เท่าใดที่สมดุลระหว่างความครบถ้วนกับต้นทุนการตัดสิน
- แหล่งสัญญาณระดับทั้งสามแหล่งใดน่าเชื่อถือที่สุด และขัดแย้งกันบ่อยแค่ไหน
- แบบจำลองที่พอดีกับ VRAM ที่มีตัดสินได้น่าเชื่อถือหรือไม่ เมื่อ RAG เปลี่ยนงานให้เป็น
  การเลือกที่มีข้อจำกัด
- ทักษะที่รายวิชาพัฒนาแต่ *มาตรฐาน* ไม่มี ควรบันทึกอย่างไร
