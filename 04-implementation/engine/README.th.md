## เริ่มใช้งาน

```bash
uv venv --python 3.13 .venv
uv pip install -e '.[dev]'

iris snapshot -v            # รายงานเกี่ยวกับมาตรฐานแห่งชาติที่ตรึงไว้
iris check <มคอ.2.pdf> -v   # ด่านตรวจความสมบูรณ์ของชั้นข้อความไทย + ซ่อมกลิฟ
iris courses <มคอ.2.pdf>    # รายการรายวิชาที่พกที่มาไปด้วย
iris link <มคอ.2.pdf> -v    # การเชื่อมรายวิชา → ทักษะ พร้อมหลักฐานที่ตรวจแล้ว
iris structure <มคอ.2.pdf>  # วิชาแกน / วิชาเลือก / ศึกษาทั่วไป รายวิชา
iris sample <มคอ.2.pdf> -o annotation/  # ตัวอย่างกำกับข้อมูล Sprint 4 ที่มี seed
pytest                      # 134 การทดสอบ
uvicorn iris.api.main:app --reload
curl localhost:8000/health
```

## สองการตัดสินใจที่ควรรู้

**SQLite ในการพัฒนา PostgreSQL ในการใช้งานจริง** ทุกโมเดลใช้ชนิดข้อมูลทั่วไปของ SQLAlchemy
สคีมาเดียวกันจึงรันได้ทั้งสองแบบ Sprint 1–7 เป็นงานนำเข้าและประเมินผลที่ไม่ควรต้องมีเซิร์ฟเวอร์
ฐานข้อมูล ส่วน `DATABASE_URL` ชี้ไปที่ PostgreSQL บนเครื่องที่ deploy จริง

**สแนปช็อตเป็นข้อมูลอ้างอิงแบบอ่านอย่างเดียว ไม่ใช่ API สด** การวิเคราะห์แต่ละครั้งบันทึกว่า
ใช้สแนปช็อตใด คำสั่ง `iris snapshot` พิมพ์ที่มานั้น และ `/health` คืนค่ามันด้วย —
เอนจินที่อ่านข้อมูลอ้างอิงของตัวเองไม่ได้ยังไม่พร้อมใช้งาน

## ตัวโหลดบังคับอะไรบ้าง

กฎคุณภาพข้อมูลจากการออกแบบถูกใช้ตอนโหลดและถูกรายงาน ไม่เงียบ

- รายการอาชีพ × ทักษะที่ `count = 0` ถูกตัดทิ้ง — **168** รายการในสแนปช็อตปัจจุบัน
  รวมถึง Python และ Pandas สำหรับวิศวกรข้อมูล
- อาชีพที่มีทักษะน้อยกว่า 10 รายการถือว่าข้อมูลไม่สมบูรณ์และถูกตัดออก — **3** อาชีพ
- บันไดอาวุโสถูกสร้างเฉพาะเมื่อทั้งสองขั้นรอดจากตัวกรองเหล่านั้น — ในข้อมูลดิบมี 13 คู่
  แต่วิเคราะห์ได้ **12** คู่

`tests/test_snapshot.py` ยืนยันตัวเลขเหล่านี้เทียบกับ
[`data-feasibility.th.md`](../../03-solution-design/data-feasibility.th.md) การดึงข้อมูล
ใหม่ที่ทำให้ข้อมูลต้นทางเปลี่ยนจึงล้มเหลวอย่างดัง แทนที่จะเลื่อนการวิเคราะห์ใต้ตัวเลขที่เผยแพร่ไปแล้ว

## ด่านตรวจความสมบูรณ์

ข้อความไทยจากเอกสาร PDF ของสถาบันมักเสียหายในลักษณะที่ไม่มีอะไรแจ้งข้อผิดพลาด
คำสั่ง `iris check` จำแนกเอกสารก่อนที่อะไรก็ตามในขั้นถัดไปจะแตะมัน

| คำตัดสิน | ความหมาย | การกระทำ |
|---|---|---|
| `clean` | อัตราเครื่องหมายใกล้ฐานอ้างอิง มีสิ่งแปลกปลอมน้อย | ใช้ชั้นข้อความ |
| `repairable` | กลิฟ ASCII ถูกแทนที่เครื่องหมายภายในคำไทย | เรียนรู้ตาราง ซ่อม แล้วรันด่านตรวจซ้ำ |
| `lossy` | ข้อมูลหายไป (เช่น `ำ` ทุกตัวยุบเป็น `า`) | สกัดใหม่ด้วยแบบจำลองภาพ ติดธงว่ามาจากภาพ |
| `unusable` | มีข้อความไทยน้อยเกินกว่าจะตัดสิน | ปฏิเสธ ขอไฟล์ที่ดีกว่า |

**ตารางซ่อมเรียนรู้จากตัวเอกสาร ไม่ใช่ฝังตายตัว** — ตารางจากไฟล์หนึ่งใช้กับผลลัพธ์ของ
ผู้ผลิตไฟล์รายอื่นไม่ได้ กลิฟที่มาแทนคือเครื่องหมายประสมตัวใดก็ตามที่ทำให้คำที่มันอยู่กลายเป็น
คำไทยจริง โดยตัวที่ยาวที่สุดชนะ และคะแนนโหวตรวมต่อ `(ฟอนต์, กลิฟ)`

วัดผลบนเอกสารจริงห้าฉบับ

```
มช        148 หน้า  MS Word 2016        สูญข้อมูล → ปรับให้เป็นปกติ → สะอาด 188.0
ม.เกษตร    28 หน้า  MS Word 2013        สูญข้อมูล → ปรับให้เป็นปกติ → สะอาด 171.0
ม.อ.      229 หน้า  macOS Quartz        ซ่อมได้ → 83%, 38 กฎ → สะอาด 175.7
ม.ศิลปากร 254 หน้า  Adobe Acrobat Pro   ซ่อมได้ → 96%, 14 กฎ → สะอาด 173.8
มศว       216 หน้า  Bullzip PDF Printer ซ่อมได้ → 92%, 13 กฎ → สะอาด 162.9
```

เทียบกับฐานอ้างอิงของเอกสารที่สะอาดที่ 171.0 เครื่องหมายต่อ 1,000 อักขระไทย
มีชุดอักขระความเสียหายที่ไม่เกี่ยวข้องกันสามชุดข้ามผู้ผลิตไฟล์ห้าราย โดยตารางที่เรียนรู้ได้
ไม่ทับซ้อนกันเลย — และ **ทุกเอกสารไปถึงชั้นข้อความที่ใช้งานได้โดยไม่ต้องใช้แบบจำลองภาพ**
ซึ่งตัด GPU ออกจากเส้นทางการนำเข้าทั้งหมด

## สถานะ

**Sprint 0–3 เสร็จและวัดผลแล้ว** คำสั่ง `iris link` รันทั้งหลักสูตรได้ครบสาย

การค้นคืนเชิงคำศัพท์วัดได้ **recall@10 75 %, @50 83 %** บนชุดพัฒนา 6 รายวิชา
ซึ่งกำหนด `k = 30` ส่วนการตัดสินรันบน `iris-adjudicator` (`qwen3:8b` ที่ `num_ctx 8192`)
ใช้หน่วยความจำ 6.6 GB ราว 4.2 วินาทีต่อรายวิชา

⚠️ **ยังห้ามอ้างตัวเลขความแม่นยำ** การให้คะแนนเทียบกับชุดพัฒนาได้ 23% แต่การอ่านตัวบท
ต้นทางแสดงว่าแบบจำลองถูกตรงที่ป้ายกำกับแคบเกินไป ความแม่นยำต้องรอด่าน Sprint 4:
ผู้ประเมินสองคน อนุญาตให้มีการเชื่อมที่ถูกต้องหลายรายการ และปิดป้ายก่อนเห็นผลของแบบจำลองใด ๆ

ยังเปิดอยู่: ครึ่งเชิงหนาแน่นของการค้นคืน ช่องทางสองภาษา และ `EMBEDDING_MODEL`
ซึ่งทั้งหมดจะมาพร้อม ablation ของ Sprint 4
